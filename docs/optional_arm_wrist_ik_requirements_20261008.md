## 1. 固定装配与控制执行

```text
策略：腕部目标 + 手指动作
  → 腕部目标速度／加速度限制（带臂模式沿用当前步限幅）
  → 每200Hz子步：连续IK参考 + 当前步速度／加速度／位置／耦合硬限
  → 满足SDK速度／加速度与URDF位置硬限的臂关节角
  → Link7 → 固定法兰 → 固定四孔连接件 → 固定手根
  → 手指／琴键物理积分 → 实际接触、按键和奖励
```

模型中法兰、连接件和手根是 Link7 的无关节后代，结构上保持完整六维刚性变换；没有独立手根 mocap 或腕部 PD 去竞争控制。策略原 TX／TY／Pitch 请求通道保留，物理中的对应六个双侧腕关节／执行器移除；TZ／Yaw仍无策略通道。实际完整位姿来自最终臂FK，不把不可达请求投影回旧腕轴来伪造重合。手指／琴键继续物理仿真，保留原质量、惯性、摩擦、接触及执行器参数；无自由度手根／掌部之间原本会被MuJoCo过滤，因此补入原跨手碰撞几何的显式接触对，并按独立mocap根区分碰撞组，确保跨手惩罚和诊断不漏计（运动学根之间只检测、没有动力学反作用）；按名称恢复编译精度，不能按旧实体编号复制。

刚性装配还须保持原手的父子接触过滤：mocap手根变为native weld 0后，引擎不再自动排除它与近端手指的父子接触。当前转换比较原／新编译模型的weld父子关系，只把丢失的关系写入物理`contact/exclude`，当前自动得到20对；原模型已有的显式geom接触对继续按引擎规则优先。无臂路径仍使用原生过滤，非相邻同手、跨手和手—琴键接触保持。排除关系写入`arm_follow_contract.parent_collision_filter`，当前活动训练从新的物理合同开始，不为旧 PT 做自动转换。

**严格的是装配关系，不是任意腕部目标都能瞬时达到。** 请求过快、不可达或接近奇异时，整套装置按可执行轨迹移动，保留请求误差；不会让手先跑远、机械臂之后追赶。策略看到实际臂状态、连续参考和请求误差，实际按键奖励来自这条连接后的运动链。

机械臂仍是已授权的运动学模型。Link0–Link7由FK更新，无臂力矩动力学、连接件质量／惯性或碰撞反作用力模拟；独立查询模型按每个200Hz子步检测臂-臂、臂-手和臂-琴冲突，并把冲突并入现有前臂接触奖励与诊断，不向主力求解器施加力。不宣称实机动力学和硬件安全已验收。没有新增未知权重的跟踪误差奖励；保留既有任务奖励和独立臂运动超限罚。

使用项目 `configs/preview/hand_connector_20260930.json` 已保存的四孔／配合面装配和12个连接件STL；配置和每个网格SHA进入臂合同。Link7的法兰中心在局部 `[0,−0.095,0]m`。法兰原点在手根系：左 `[+0.0135,+0.004,−0.026]m`，右 `[+0.0135,−0.004,−0.026]m`；两原点相距约29.567719mm，保留此固定关系，不强行重合。完整朝向同样固定。

`--arms` 必须显式给 `--arm-initial-right-deg` 和 `--arm-initial-left-deg` 各7角，J1–J7、单位度、默认空；缺参／越界在申请GPU前拒绝。安装默认由当前 `configs/preview/hand_connector_20260930.json` 的四孔刚性装配计算 `link7_to_hand`，不读取旧预览 seed／基座；自定义 `--arm-mount` 必须与当前已确认四孔装配一致，否则明确拒绝。新安装必须更新对应装配合同，不能只移动手部或显示件。

在已抬高的t=0，由完整手根位姿、用户初始七角和安装变换一次反算固定基座。W为手根、L为Link7、B为臂基座：

```text
T_world_B = T_world_W(0) · inverse(T_L_W) · inverse(FK_B_L(q0))
T_world_W_actual(t) = T_world_B · FK_B_L(q_cmd(t)) · T_L_W
```

基座不随动作重算。保存世界／钢琴两系完整基座；reset回到同一装配初态，只清指定环境的q/v、IK参考和误差历史。`policy_v1`准备段作为腕部目标的原1秒quintic升降请求，通过同一套IK／硬限执行，不另开支架移动手。无准备段也支持。右手仍为项目镜像推导，螺孔配合／法兰钟向／硬件标定保留TODO(V32-MOUNT-01)。

## 3. 连续IK与硬限

当前控制器以**上一时刻IK参考**为种子，求位置边界内的连续参考 `q_ref`，然后直接将该参考裁剪到当前步速度、加速度、位置和 CCS696 耦合可行盒；不根据到目标的剩余距离提前刹停。位置边界仍使用端点可行性速度上限，防止到达 URDF 边界时下一步被迫违反加速度硬限。有限迭代IK仍可能有局部残差，不承诺任意目标可达或全局最优。

| 左右两侧关节 | 速度硬限 | 加速度硬限 | 软阈值 |
| --- | --- | --- | --- |
| J1–J2 | π rad/s | 2.5π rad/s² | 各自硬限的95% |
| J3–J7 | π rad/s | 5π rad/s² | 各自硬限的95% |

来源为项目 `configs/preview/m6_sdk_joint_limits.json` 与双侧URDF位置范围。每物理子步h=.005s，以双精度保存q/v和参考；硬限是**下发运动学关节轨迹的离散差分限制**。原腕/TCP目标限幅保持，不能把目标上限说成真实手指qvel/qacc保证。

上游腕部目标生成只保留当前步的目标速度、加速度和位置边界限幅，不再为原始请求计算额外的离散可停速度；目标硬限数值不改，当前控制合同为 `target_motion_contract.controller=wrist_target_rate_limits`。

IK为阻尼最小二乘，有界回溯、12迭代、姿态权重.15m、阻尼.008；候选和最终轨迹均必须满足CCS-696 J6/J7耦合。数值无效、可行区间为空或任一硬限／耦合复核失败明确抛错，双臂均通过才提交，不静默重置／放宽限制。

## 4. 奖励、观察与诊断

独立 `arm_motion_limit_penalty` 的参数和公式保持，输入改为**腕部请求产生的连续IK参考**：

```text
v_req = (q_ref − q_cmd_prev) / h
a_req = (v_req − v_cmd_prev) / h
e = max(0, |v_req| / v_soft − 1, |a_req| / a_soft − 1)
r_arm = −5 × min(max_左右关节_两类导数_本控制步子步(e) / .1, 1)
```

weight=1，每控制步最多−5，不乘dt、不跨子步累加，与原手指／腕／TCP运动罚独立。软阈值上方5%扣2.5、10%扣满5；满罚原始需求对应SDK硬限104.5%。没有额外IK残差罚。所有当前奖励的完整取值只在[唯一总表](reward_defaults_20261006.md)维护，开始训练仍打印最终完整奖励。

- 策略动作维数保持：耦合入口31。新增臂观察共54维：每侧依次q7、v7、IK参考7、世界位置误差3、世界旋转误差3，先右后左；单位rad／rad/s／m。以实际臂q可恢复完整实际手根位姿。
- 原手部关节观察中已经不存在的腕轴槽位保存reset常数作为占位，不能当真实腕qpos；新臂状态承担实际根位姿表达。该语义写入当前 Cartesian 掌位移控制合同，禁止与旧PT混用。
- 腕PD移除后，功率项对40个实际手指执行器计算，不虚构运动学机械臂功率。无臂分支仍按原腕＋手指执行器计算。
- 保留finger-clearance与键底接触诊断；臂模式使用真实手根完整位置／朝向，已验证胶囊FK与物理几何一致。当前两个动作投影均关闭；臂模式若显式开启旧投影／腕互锁会拒绝，不能沿用只支持竖直支架的保护假设。
- 每子步先更新唯一装配根再执行物理和接触采样；仍绕过整控制周期capture，保留单步物理图与学习器设置。逐环境局部reset不推进其他环境。
