用户明确要求修复上一轮已解释的两项缺口：正确键正奖励只看 20 Hz 末端、未触发琴键仍获很高连续分。按此前方案实现独立可选的物理子步均值和真实激活混合，`run.sh` 显式开启两项；通用 Python/历史 JSON 缺字段保持旧规则。

已对照论文 pp.10–12 §2.9 式13–14：论文按键项为 `0.6*r_on + 0.4*exp(-1.25*N_wrong)`，当前 Shadow 项为 `0.5*r_on + 0.5*无错键`。本次用户选择工程适配，只调整 `r_on` 的时间归约与激活成分，保留所选模式的外层系数、错键项、和弦选项、dt 缩放和权重；不称为论文公式复现。

不改变20/200 Hz、正式F1定义、乐谱、指法、模型机械限位、腕部限速、三个3e-4学习率、网络、gamma或采样复用预算。没有开启新的5M正式训练。

## 修复后的公式

对当前目标键集合 G、一个控制周期 S=10 个物理子步：

```
g(x) = 原连续键程高斯分
a(s,k) = 与正式按键判断相同的物理触发布尔值
r_on = mean_s(mean_{k in G}((1-λ)*g(x(s,k)) + λ*a(s,k)))
```

G为空时 `r_on=0`；子步使用均值，不将总奖励放大10倍。当前脚本 λ=0.5，正确键正项仍占原按键奖励的0.5预算。触发值直接使用物理子步采集的 `key_activation_history`，不从归一化键程反算，避免白/黑键范围不同及浮点边界误判。

| 情况 | 原目标键正分 | 新目标键正分，λ=.5 |
|---|---:|---:|
| 全周期完全按下 | 1 | 1 |
| 只在最后1/10子步完全按下，其余完全未按 | 1 | 约0.10011 |
| 白键持续刚低于触发阈值 | 约0.94123 | 约0.47061 |
| 黑键持续刚低于触发阈值 | 约0.97863 | 约0.48931 |
| 当前无目标键 | 0 | 0 |

此表是 `r_on`，不是完整总奖励。白键未触发但没有错键时，完整 Shadow 按键项从约0.97061变为0.73531；仍保留“没有错键”的0.5分。连续键程部分保留接近信号，而跨过真实阈值获得明确增益。低于阈值的单键正分最多0.5，无法再接近满分。

只开子步均值可单独定位时序作用；只加激活占比可单独定位浅按阈值作用。两项均关闭时走原计算分支，不通过无意义的重算改变历史浮点顺序。

## 其他影响F1的问题及处理次序

详见 [独立审计](f1_additional_audit_20260928.md)，其中区分实际事实、设计取舍和待验证因果。

1. **早期replay只覆盖准备期。** 512环境同步reset，4999条随机样本仅约10控制帧/.5秒，音乐尚未开始便学习。建议另作完整谱面预填对照；当前178帧×512=91,136条样本只是本曲整回合数量，应按任意乐谱实际长度算，不能写死小星星窗口。该项会改变学习启动预算，未擅改。
2. **提前定位稀释当前指法。** 当前/未来指法共享平均分母；本曲149有音帧中45帧受影响，当前整体系数最小1/3。短D5两帧为1/2和3/4。下一项建议单独比较固定当前/未来预算，不能直接推断已证明它导致漏音。
3. **短D5的动作本身未形成有效按压。** 漏音时右食指MCP目标约.249/.102rad，后续成功D5约1.094rad；同时PIP姿态也不同。该证据不能简化为MCP单关节根因，但不足以把腕速当唯一原因。仍需逐子步末端位置和接触因果检查。
4. **连续同音量化可能删除极短音符。** 已复现20 Hz下单帧重复音被转换器用于分音的空帧吞掉。本曲相邻D5也有一帧被用于分音，但那个完全漏按的短D5目标仍存在，不能用转换问题解释它。更改分音/采样规则会改变评分合同，需独立设计。
5. **曲末没有松键验收尾段。** 最后C5目标直到轨迹终点，现有评分不能核验最终释放；不能通过修改正式目标来静默提高F1。
6. **20 Hz高分不保证200 Hz高分。** 当前best门槛的micro-F1仍为20 Hz；应继续查看独立200 Hz曲线。没有改变正式门槛或阈值。
7. **奖励本身也是策略输入。** 当前观测含上一帧reward；新奖励不仅改变critic学习目标，也会改变旧actor下一帧输入。因此仅加载旧权重、尚未学习时的F1也可能改变。旧权重必须显式迁移并重新验证，不能承诺开关即使旧best自动到.99。

局部reset先存终态再重置，没有发现reset观测混入终态的错误；末曲discount=1是现行CPU/Shadow合同，本次没有把它当缺陷改掉。未修改gamma、增加qvel/新观测、提高频率、取消腕速或扩大humanoid。
