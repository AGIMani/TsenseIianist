后续入口变更：本页为20/200Hz三组历史实验，结果见[三组F1分析](coupling_f1_analysis_20260930.md)。当前HPC train已默认40/400Hz耦合完整观测，下文历史启动命令须配合对应源码归档；[当前配置](coupled_40hz_training_20260930.md)。

## 1. 用户确认的范围

用户确认：食指、中指、无名指和小指的末节沿指尖方向轴线，与琴面尽量形成约 60°；拇指保留原控制。PIP/DIP 仍是物理关节，由 MCP 与腕部姿态计算从动目标。

本次参数默认关闭：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `--finger-coupling` / `--no-finger-coupling` | 关闭 | 启用/关闭两手四指的从动控制 |
| `--finger-coupling-angle` | 60 | 有向末节轴线朝琴面向下的目标夹角，单位度，必须在 0°与90°之间 |
| `--coupling-reduce-observation` / `--no-coupling-reduce-observation` | 开启 | 仅在耦合启用时生效；是否移除从动关节位置和上帧控制槽位 |

末节轴线由 **DIP 转轴位置指向包内指尖定位点**定义；琴面法向从编译模型中静止琴键碰撞几何读取。这里的 60°是末节相对琴面的方向，不是 DIP 关节自身屈曲角。方向计算使用模型变换，不根据 `Pitch` 名称猜测世界方向。

包内指尖定位点仍是几何推导的暂定点。TODO(V32-07)：真实指垫中心、实际触键面及材料形变尚待标定。因此这一夹角不能称为已标定的真实指腹触键角。

## 2. 控制器实际如何执行

两手共八根非拇指各移除两个策略输出：PIP 和 DIP。策略继续控制它们的 MCP 和 swing，拇指、保留的腕轴及踏板继续沿原动作映射执行。在当前无臂、TZ/Yaw 结构移除的入口中，动作从 47 维变为 **31 维**。

PIP/DIP 的 MuJoCo 关节、驱动器、惯量、阻尼、力限制、接触和机械限位均保留。当前物理模型仍是 134 个坐标、46 个驱动器。31 是策略动作维度，不是物理自由度数。

每个 20 Hz 控制帧执行：

1. 按当前 Direct 动作映射得到 MCP 等策略控制通道的物理目标，执行已有腕部限速。
2. 从实际物理状态读取腕部和 swing 姿态、各指关节位置；使用本帧下发的 MCP 目标计算候选末节方向。
3. 在 PIP 允许范围内取 17 点候选，加入 origin 和实际 PIP 位置；对每个候选解析求取 DIP 解，并裁剪到允许范围。
4. 在初选 PIP 周围做 9 点局部细化，同时保留原候选。方向误差在 0.05°以内时，优先选 PIP/DIP 相对 origin 位移平方和较小的解；没有满足阈值的候选时取角度误差较小的解，并报告 `coupling_infeasible`。
5. 将 PIP/DIP 目标写入原物理驱动器，在接下来十个 200 Hz 子步中由原动力学和接触求解执行。

该求解每个控制帧作用于八根耦合手指，包括准备段、休止段和当前闲指。`coupling_active` 仅用于按当前谱面用指划分诊断，不是控制器的启停条件。

控制器不逐步重写 qpos，也不把从动关节瞬间移动到目标。实际关节可能因为驱动力、惯性、接触及腕部变化而滞后。几何目标角接近 60°不能证明实际击键角接近 60°；可行方向也不能证明存在无碰撞的运动路径。求解器是有界候选搜索，`infeasible` 表示本次搜索没有找到阈值内候选，不能视为完整可达性证明。

当前兼容限制：

- 可与当前 `wuji_cartesian_v1` 机械臂跟随器组合。机械臂不增加直接关节动作；掌位移请求仍经连续 IK 和硬限轨迹，指尖耦合只重映射八根非拇指手指的 PIP/DIP 目标。
- 带臂训练必须使用显式双侧七角、`--disable-wrist-tz --disable-wrist-yaw` 和当前连接件合同；`--arms` 与 `--no-arms` 互斥。组合模式仍需单独验收实际指尖跟踪、IK 可达率和观察／动作合同。
- 闲指净空投影和用指按压许可两个动作保护必须关闭；现有 HPC/run.sh 默认符合该条件。
- 不接受再为 PIP/DIP 从动通道单独设置目标裁剪或变化率限制；腕部现有限速继续有效。
- 几何诊断和辅助奖励仍按原设置计算，三类物理接触及原奖励配置不因启用耦合而取消。

## 3. 完整观测与精简观测

当前提前定位默认 0.15 秒，包含 50 维提前指法信息；1 秒策略准备保留 1 维准备进度。`frame_stack=1` 时：

| 实验组 | 耦合 | 策略动作 | 观测 | 所检验的问题 |
| --- | --- | ---: | ---: | --- |
| B：基线 | 关闭 | 47 | 1231 | 当前独立关节策略参照 |
| C：耦合、完整观测 | 开启 | 31 | 1231 | 简化动作并使用60°从动控制是否有效 |
| R：耦合、精简观测 | 开启 | 31 | 1199 | 相同从动控制下，减少32维观测是否有效 |

精简观测移除：

- 八根指的 PIP/DIP 实际位置，共 16 维。
- 上一帧完整物理控制中的对应 PIP/DIP 槽位，共 16 维。

其余物理信息、MCP/swing、拇指、腕部、谱面前瞻、奖励观测、准备进度和提前指法保持。完整观测组保留从动关节真实位置与上帧实际下发目标；它没有恢复独立 PIP/DIP 策略输出。

从动关节仍有实际误差和接触，因此精简观测会隐藏部分物理状态。这是需要实测的观测取舍，不能称为无损压缩。使用更多 frame stack 时，会按冻结字段布局删除每个栈位置对应槽位；1199 仅对应本次默认单帧布局。

### SAC 的动作维度适配

现有 SAC 的目标熵规则是 `−0.5 × action_size`。因此：

- 基线 47 动作：目标熵 **−23.5**。
- 两个耦合组 31 动作：目标熵 **−15.5**。

三个学习率、初始温度、网络隐层、batch、更新比例等保持，但目标熵会按既有规则随动作数变化。B 对 C 的差异包含从动控制、动作空间和目标熵的维度适配，不能把所有差异归于少16个输出。C 对 R 保持31动作和相同目标熵，用于较清楚地检验观测精简的影响。

## 4. 三组训练命令

全部从头训练，seed42、512 环境、5860 向量步，即 **3,000,320 条样本/组**。评估保持每100步3回合，并采用本轮验证后的同一种 GPU 执行方式。命令明确把连续达标次数设为5862，确保三组跑完相同初筛预算；best 资格与质量诊断仍保存。

```bash
# B：47动作 / 1231观测，基线。
bash scripts/hpc/submit.sh train \
  --no-finger-coupling \
  --vector-steps 5860 --seed 42 --target-consecutive-evals 5862

# C：31动作 / 1231观测，耦合但保留完整物理观测。
bash scripts/hpc/submit.sh train \
  --finger-coupling --finger-coupling-angle 60 \
  --no-coupling-reduce-observation \
  --vector-steps 5860 --seed 42 --target-consecutive-evals 5862

# R：31动作 / 1199观测，耦合并精简从动观测。
bash scripts/hpc/submit.sh train \
  --finger-coupling --finger-coupling-angle 60 \
  --coupling-reduce-observation \
  --vector-steps 5860 --seed 42 --target-consecutive-evals 5862
```

以上命令继承 HPC 默认的两卡采样/学习流水、TX/TY 1 m/s、Pitch 4 rad/s、提前定位0.15秒和3环境批量评估。其余控制、模型、Direct MCP上限1.3 rad、奖励、准备/释放时间、512环境、batch1024、更新比.25、三个LR3e-4及整曲预填保持。耦合实验不同时加入“取消当前指法优先”或“分阶段指法”奖励改动。

每个作业有独立源码归档、训练目录、完整配置和检查点。不能把旧47维策略权重直接当作31维策略的可兼容恢复；本次三组都不使用旧检查点。

## 5. 如何判断结果

### 执行验收

在 Slurm 内确认三组的实际动作/观测形状、正确动作通道、控制目标范围、有限状态、局部reset、完整回合、SAC更新、从源码重建及检查点重载。性能测量记录样本/秒、学习和评估时间、求解开销、显存与实际更新数。动作和观测减少不等于物理仿真更快；从动求解也会增加计算。

功能短训仅用于以上正确性验收。3M 初筛评估长期趋势，不用十万级功能短训宣布 F1 改善。

### 音乐与物理质量

对比 best、final 和末50万样本区间，并使用一致评估配置与重复回放：

- 音乐段20Hz F1及每回合最低分。
- 200Hz音乐 micro F1、漏目标键采样、错键采样。
- 逐音完整漏弹、提前松键、起音延迟，尤其此前失分的右小指/右食指/右中指及左拇指。
- 同手/跨手碰撞、键底/键侧接触和准备段误触。
- 从动目标误差、实际角度误差、到限比例、搜索未达阈值比例，分全部手指和当前谱面用指报告。

拇指没有加入本次耦合，其失分若改变，可能来自整手运动和训练策略变化，不能归因为拇指也被60°约束。

### 角度诊断的口径

`CouplingMetrics` 每个控制帧读取一次数据：目标方向来自本帧求解，实际方向来自物理执行后刷新得到的末节姿态。默认是 **20Hz控制周期末**采样。`active` 表示当前谱面指定该指，不要求本帧真实接触到琴键。

通用诊断的`requested_physical_action`在动作变换前记录，其中PIP/DIP槽是中性占位，
不代表策略独立请求的从动目标。检查从动目标应读取`applied_physical_action`和
`coupling_target_angle_deg`；实际响应则读取物理qpos和`coupling_actual_angle_deg`。

因此，当前用指的平均/最大实际误差能说明跟踪情况，不能单独证明“每次物理接触时均约60°”。若要验证触键瞬间，需额外在200Hz物理子步按真实手指—琴键接触筛选角度，或进行同频详细回放。本次报告应保留这一测量限制。

C 优于 B、R 不优于 C：可保留完整观测，仅评估是否采用从动控制。R 优于 C：才支持本任务中精简观测有收益。三组若都未超过基线，保持耦合默认关闭；若有候选，再做相同条件的完整5M和不同训练种子确认。最终仍按音乐0.99及物理质量目标验收。

## 6. 配置与检查点合同

训练 `config.json` 和 checkpoint 保存：

- `finger_coupling`：规范化选项、角度和观测开关。
- `finger_coupling_contract`：实际关节/动作索引、轴线、指尖定位方向、琴面法向、物理范围、origin、求解器和更新方式。
- `coupling_observation_contract`：原始尺寸、保留/删除索引、stack布局及附加字段规则。
- `policy_action_names`、实际 `action_size` / `observation_size`、实际 `target_entropy`。

恢复和独立评估会重新构建模型并比较合同。角度、从动关节或观测布局不匹配时拒绝静默加载。旧无耦合 checkpoint 仍按缺项为关闭的旧合同处理，且仍受原源码散列与任务合同检查。
