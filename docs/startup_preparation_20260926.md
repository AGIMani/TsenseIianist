## 本轮决定和结果

用户明确要求：“先记住当前的姿态记为 origin，再用抬高的姿态作为训练的起始姿态 initial，然后从 initial 1 秒平滑过渡到 origin。”

新 `run.sh` 默认采用这条固定准备轨迹。手形、TX／TY／Pitch／Yaw 保留当前值，双手仅沿世界 Z 同时抬高 0.02 m；从抬高位置立即开始回落，1 秒到达 origin。没有先停留 1 秒。准备期间关节保持初始目标、踏板关闭；1 秒后才交给策略，并从乐谱第 0 帧开始。

- [准备视频](../preview/outputs/preparation/lift_2cm_1s_shadow_20260926/preparation.mp4)：1 秒运动，随后约 1 秒停在终点供观察。使用当前 Shadow profile，尚无演奏策略。
- [origin 快照](../configs/poses/origin_20260926.json)、[initial 快照](../configs/poses/initial_20260926.json)：本次源姿态记录；不是另一套运行时配置入口。
- [完整命名关节、目标及实际世界位姿](../preview/outputs/preparation/lift_2cm_1s_shadow_20260926/origin_initial.json)、[物理验收报告](../preview/outputs/preparation/lift_2cm_1s_shadow_20260926/report.json)。

当前 origin 的安装位置为 `(0.18, ±0.15, 0.10)` m，应用 TY=0.04 m 后实际手根约为 `(0.14, ±0.15, 0.10)` m。initial 实际手根约为 `(0.14, ±0.15, 0.12)` m。左右 Yaw 均 0.15 rad，Pitch=0。`attachment_position` 是安装变换，不能直接当成应用腕关节后的手根位置。

## 为什么原视频曲首仍会乱弹

对照对象是已完成的 `sac-twinkle-shadow-sync-5m-20260925-171119-593333`，保留了旧源码归档再进行本轮修改。原训练于 9 月 25 日 22:45 完成；本轮没有继续向其中写入。

### 1. 早期已有大动作，末期仍有曲首集中误触

step100 的确定性整曲评估 F1=0.120，腕 TX 目标最大跳变 0.977 m；step500 为 F1=0.152、最大跳变 0.814 m。这里的峰值来自整曲，不能全部归到曲首。最早留存的 step500 检查点补导回放有 102 个错键帧。

最终视频的 7 个错键帧中，有 5 个落在策略接管后的首秒；按 200 Hz 音频事件计，首秒有 6 次错音起音。训练确实改善了后半段演奏，但开场问题没有消失。日志没有记录探索期全部动作，无法逐帧复原每一个早期训练环境。

### 2. reset 是干净的；第一条策略命令已大幅偏离 origin

原 reset 的关节速度为 0、88 键都释放、踏板为 0。最终策略第一条目标包括：

| 控制量 | reset → 首条策略目标 |
| --- | --- |
| 右 TX | 0 → −0.157759 m |
| 左／右 TY | 0.04 → 0.001199／0.003163 m |
| 左／右 Pitch | 0 → +0.197337／−0.165688 rad |
| 最大单指目标变化 | 1.331078 rad |

乐谱 t=0 已要求 MIDI48/C3（L5 左小指）及 MIDI72/C5（R2 右食指）。策略既要从 origin 移到演奏位置，又要立即触键。目标阶跃是实际证据；接触挤压仍可能影响后续路径，不能把所有误触都归为同一个原因。

### 3. 听得到的短错音，训练有时没有采到

声音按每 5 ms 的实际琴键状态生成；当前奖励和 F1 按每 50 ms 控制周期末状态计算。错 MIDI71 曾在 0.270–0.290 秒出现，错 MIDI56 曾在 0.805–0.845 秒出现：它们在两个控制采样点之间完成按下和释放，听得见，却没进入控制端点的错键项。踏板又在 0.005–2.155 秒开启，使早期错音持续更久。

因此“F1 较高”不能证明音频没有短暂杂音。本轮保留 Shadow 奖励采样规则，没有自行启用额外惩罚或修改按键公式。

### 4. 随机探索不是准备时间

前 4999 条随机 transition 分到 512 个环境，每个环境只覆盖约 10 个控制步／0.5 秒；之后仍按 SAC 随机策略探索。这是训练启动时的一次性采样安排，不是每回合的准备阶段。单独增加 `initial-buffer-time` 也只会插入空白乐谱，策略仍能在空白期间乱动。

逐阶段证据、视频及统计口径见[曲首审计](../preview/outputs/diagnostics/startup_20260926/README.md)。

## 新流程如何运行

```text
当前源姿态 origin（完整保存）
           ↓ 世界 Z +0.02 m，关节角不变
initial → 固定目标、1 秒平滑回落 → 实际准备终态 ≈ origin
                                      ↓
                      策略接管、乐谱第 0 帧、SAC transition 开始
                                      ↓
                      正常整曲 → 保存终止 transition → 局部 reset
```

回落曲线为 `z(u)=z_origin+0.02×[1−10u³+15u⁴−6u⁵]`，`u=t/1s`；起止速度和加速度均为 0。每 5 ms 更新支撑位置并真实求解一次 MuJoCo 物理，共 200 个物理步／201 个状态。末帧保留实际计算结果，没有把所有 qpos/qvel 强制写回 origin 来掩盖误差。

TZ、Yaw 仍从策略物理模型删除：134 个标量坐标、46 个驱动器、47 个动作、1180 维观测保持。升降由两个独立运动学父节点执行，不扩大旧 TZ 的 `[-0.025,0]` 范围，也不让策略增加一个抬升动作。这是指定位置的准备流程，不模拟机械臂惯性或硬件升降台动力学。

### 并行 reset 与性能

固定准备过程没有可学习动作，因此每个场景实例只在独立 CPU MuJoCo 世界计算一次；GPU 环境初始化／回合重置直接复制其终态。重置 world 0 不会推进 world 1 的物理时间或修改其状态。视频／预览显示这次真实计算的完整准备轨迹，随后显示从同一终态开始的 GPU 策略演奏。

这意味着 GPU SAC 的第一条训练 transition 从“准备完成后”开始，准备帧不插入 replay、不计算奖励/F1、不消耗乐谱时间，也不增加每回合 20 条固定动作样本。`config.json` 同时存储 `preparation` 参数和 `preparation_contract.origin/initial/terminal/report` 完整状态与报告。

重放数组中，`rollout.npz` 仍只包含策略段；独立 `preparation.npz` 保存准备段。视频时间比策略时间多 1 秒，200 Hz 实际按键音频同样前移这 1 秒，不能仅给画面加前缀而让音频错位。

## 本轮验证与边界

当前 Shadow profile 的 1 秒准备轨迹：琴键激活次数为 0，生成音频峰值为 0；手关节回位误差最大约 `3.88e−9 rad`，腕平移误差约 `2.17e−14 m`，终态最大速度约 `1.33e−7`（含 rad/s 与 m/s 分量）。全模型 `0.000623 rad` 的位置偏差来自琴键静态重力回落，不是手指回位误差。

单元测试覆盖动作/物理维度、抬升方向、201 帧轨迹、非法时长、真实终态不投影、GPU 局部 reset 不污染其他环境、checkpoint 准备合同及旧合同兼容。短训、正式入口回放与具体输出记录见[修改日志](change_log.md)。本轮只做短程验收，没有启动新的 5M 长训。

**V32-START-01：准备段安静不等于策略接管后也安静。** origin 与原起姿相同，旧首条大目标可能只是延后 1 秒。新流程还需新策略长训后的首秒实测；如需限制接管阶跃，应另行决定动作过渡／限速及相应训练合同，不能仅修改视频。

**V32-START-02：200 Hz 音频与 20 Hz 奖励的短错音盲区仍存在。** 可后续比较子步错键累计，但这会改变 Shadow 奖励采样语义；当前没有默默更改。

原 V32-04 驱动/动力学校准、V32-06 接触及 V32-SAC-03 长期稳定性仍保留。GPU 接触仍不保证逐 bit 重放一致。源姿态 GUI 未作桌面窗口验收，离屏 NVIDIA EGL 渲染已验证。

## 为什么本次训练要 5 个多小时

主要是学习预算增加，详细证据见[速度审计](training_speed_audit_20260926.md)：

| 指标 | 前一轮 | Shadow 同步后 |
| --- | ---: | ---: |
| 实际 SAC 更新数 | 593,088 | 4,995,193 |
| 每向量步稳定更新数 | 64 | 512 |
| 耗时 | 45 分 57 秒 | 5 小时 34 分 25 秒 |

耗时增加 7.28 倍。实测 512 环境物理约 29 ms／向量步，而 512 次 SAC 更新约 1.95 秒；学习更新占正常步骤耗时约 98.4%。物理 CUDA graph、编译学习器与融合优化器都已开启。评估由 20 次增加到 489 次，日志差分估计额外评估约占总耗时 5%，也有影响，但不是主因。

本轮保留已确认 Shadow 每样本一次更新。直接降回 0.125 次更新会改变学习预算；保留预算的完整学习器图执行、减少同步等工程优化尚待独立测量和数值验证，不能承诺恢复到 46 分钟。
