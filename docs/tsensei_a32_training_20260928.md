## 模型问题及修复

- 原包只有左手，仍以正确的极向量／轴向量规则镜像右手（TODO V32-10）。
- 新小指已经是 MCP/SWING/PIP/DIP；只把 SWING 规范为 swing，不能套旧 rotaback 链的重命名。
- 新 base_link.STL 单独使用毫米，其他 21 个 STL 使用米。在派生 URDF 的该 link 视觉／碰撞 mesh 写入 `.001` 缩放；厂家源文件保持原样，尺寸证据及 SHA 写入 model_derivation.json。
- 新 base_link 是 ID 掌壳，固定 palm link 是小安装块，与旧物理角色互换。沿用 Shadow 式简化方式：掌壳保留 mesh，安装块 box，20 个指段 capsule，每手仍 21 primitive＋1 mesh。按实际掌壳同步 forearm 名单及既有掌壳—拇指装配排除，奖励公式不变。

- 全量替换左右 mesh 目录，避免旧 OBJ 优先加载而误用旧外观。当前运行 URDF 为 `assets/urdf/TsenseI_left.urdf` 和 `TsenseI_right.urdf`。

## 提前定位为何可以换曲使用

程序从乐谱的 `[时刻,10手指,88键]` 指法表中，给当前空闲指查找未来 3 帧内最近一次任务。
目标 XY 来自那枚琴键，Z 为未按下键顶上方 5 mm；策略额外看到相对 XYZ、距起音时间与有效掩码，共 50 维。
当前仍在弹持续音的手指不会被提前切走；不会跨回合末尾寻找目标。未来接近分不超过 .5，和当前用指共享原来总上限 1 的指法预算。

该规则不读取曲名或硬编码小星星位置，所以其他**有完整有效指法、音符时序且机械可达**的曲目可直接采用相同入口开训。
它不自动生成指法；普通无指法 MIDI 仍会被当前 GPU 任务拒绝。换曲可复用算法，但策略仍需训练／评估，大跳和高速乐句也可能需要调提前时间，不能保证 .15 秒足够。
