# step-15000 起始前冲、低角度视频与当前训练速度

日期：2026-09-18。诊断对象是用户刚看到的 `sac-20260918-135539-423462/step-15000.pt` 视频。相机调整复用该视频的原轨迹，不更换策略、不修改控制或奖励。

## 1. 起始前冲：第一条绝对位置命令跳变

视频第0帧为reset姿态，显示0.05秒；下一帧已经执行100个0.5ms物理子步。看起来一帧“冲出去”，实际是50ms内的快速运动。

策略输出归一化动作 `a∈[-1,1]`，`PianoScene.step()`按 `low+(a+1)/2*(high-low)` 转成绝对位置目标，立即写入 `ctrl` 并保持整个50ms周期。当前没有起始过渡、命令插值或命令速度硬限幅。

| 右腕TX | 0mm | +85.04mm | +27.84mm |

腕TX／TY不是世界X／Y：当前模型TX沿世界+Y，TY沿世界−X。右腕基座首步世界位移为 `[-22.37,+27.84,+1.29] mm`，左腕为 `[-12.95,−5.08,−0.83] mm`。因此画面中的前后／横移不能直接按关节后缀理解。

首条命令按初始位置误差计算，有26个手指执行器和4个腕转动执行器要求的未裁剪伺服力矩超过各自限值。右腕TX／TY初始位置驱动力分别约25.51N／21.45N（均未超过50N力限）。这说明第一条动作本身已足以启动快速运动；力矩限幅并不等于速度限幅。

### 是不是先撞到东西才被弹出去？

两组独立GPU复查：原动作前1秒每5ms采样；前100ms每个0.5ms子步采样，并各做保持初始控制0.5秒的对照。

- 原reset几何没有手部负距离接触；保持初始控制的对照也未检测到手部负距离接触。
- 第0.5ms腕已开始移动；右腕TX速度约0.184m/s。
- 每子步检查最早的手部接触在8ms：左中指末节与黑键33；右中指与黑键54在15.5ms接触。
- 前100ms没有采到手内自碰撞、左右手互撞或琴箱接触。
- 前1秒的5ms采样中，最早手内自碰撞在0.430秒：右中指根部侧摆连杆与右无名指根部侧摆连杆，采样峰值约5.24N。

**主因是首步主动目标跳变，随后触键产生反作用；不是初始穿插或手内碰撞先把手弹出去。** 接触会影响之后的运动，不能据此说接触完全没有作用。每0.5ms读取的是求解器实际积分接触表；动力学重播并非逐位一致，前100ms与原视频的最大平移偏差约0.00060mm、角度偏差约0.0000358rad。接触力是仿真单接触力，不是实机标定值。

第一拍已要求按键27、51及踏板，没有预备空拍。当前检查点仍使用原五项奖励＋权重0.2的自碰撞惩罚，未启用新实现的命令速度／加速度／自然姿态项。快速进入得分手型缺少这些专项约束，是合理的策略动机解释；没有消融实验，不能量化各奖励对首步动作的因果贡献。

### 与论文重合、仍由用户决定的改动

- 论文pp.6–8：2.5ms×10、40Hz控制、子步插值。当前0.5ms×100、20Hz、目标保持。子步插值或起始过渡会改变训练与回放动力学，不能只在视频中加平滑就宣称策略问题已解决。
- 论文p.11式16–18：命令速度／加速度／超速惩罚。项目已有可选公式，但本检查点没有训练这些项；启用需要新训练，并遵守用户填写动作单位／映射的决定。软惩罚也不保证硬速度上限。
- 准备空拍或重新设计reset姿态会改变任务起点，属于V32-PAPER-01/08范围，不能自动套用到原检查点。

## 3. 训练速度：尚无证据表明已到极限，主要成本在物理和学习

最新训练现已完成：20,000向量步、5,120,000条transition、608,032次更新，总耗时8778.72秒（约2小时26分），包含初始化／评价／保存，约583条transition/s。末条训练日志的循环平均吞吐约584.5/s。

训练结束、没有其他训练／回放进程时，用step-15000进行单独短测：256环境、batch4096、每向量步32次更新、自碰撞权重0.2，整周期物理graph／学习器compile／fused Adam全部开启，TF32关闭。16批预热物理数据重复填满262144条replay，学习器预热后测12轮，不保存新的策略。

### 为什么仍然慢

整轮要计算约5.12亿个单环境物理子步；100子步graph只减少提交开销，没有省掉碰撞检测和约束求解。学习端每新增256条样本做32×4096次样本使用，重复使用比例512；整轮608032次梯度更新也不是小工作量。训练主循环没有相机渲染或音频合成，调整视角不会提高训练吞吐。

### 下一步优化优先级与边界

1. **保留算法语义的工程优化**：用GPU kernel计时进一步分解物理碰撞／求解器，检查可减少的中间计算与数据搬运；学习器仍有逐参数Polyak更新、32次独立更新调度和每次 `torch.isfinite(...).all()` 的主机同步。可研究融合、设备端累计错误状态和更完整的更新图，但需要确保数值／RNG／报错语义，不承诺未经测试的收益。
2. **并行环境数扫描**：显存尚有空间不等于计算资源空闲。256→512／1024可能改善部分核的利用率，也可能增加物理成本；若固定32次更新，则每样本更新比会下降。公平速度对照应记录并保持更新比，不能把减少学习量称为纯加速。
3. **需要用户决定的任务或数值变化**：增大物理步长、减少求解迭代、简化碰撞形状会影响硬接触与穿透；TF32／混合精度会改变数值；减少32次更新或batch会改变学习预算。与论文pp.6–10的控制／SAC参数有重合，当前没有替用户修改。

固定当前物理耗时，假设学习更新完全不要时间，短测理论上限也仅约1.55倍；这不是可实现承诺，而是说明“只继续优化神经网络”无法获得数量级提速。要显著提速，需要同时解决物理成本。
