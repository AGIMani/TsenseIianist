# 指法、时间与三维姿态预览

启动本地编辑器：

```bash
./launch_fingering_editor.sh
# 或导入其他 NoteSequence 二进制文件
./launch_fingering_editor.sh /绝对路径/example.proto
```

默认打开用户提供的 `results/exper024/input_sources/015-5_fingered.proto`（269 音符，约 24.0521 秒）。也可以在窗口中点击“导入 proto”。这里的 `.proto` 是已序列化的 `note_seq.NoteSequence`，不是 protobuf schema 源文件。

## 编辑

1. 点击时间轴音符或列表，选择一个音符；三维姿态定位到它的起音时刻。
2. 点击下方十指按钮修改该音符的 `part`。右手拇指、食指、中指、无名指、小指依次为 **0、1、2、3、4**；左手依次为 **5、6、7、8、9**。
3. 编辑“起音 / s”和“松键 / s”，点击“应用时间”。时间使用原始秒值，不量化到训练控制帧。要求有限数且 `0 ≤ start < end`。
4. 撤销/重做支持指法和时间修改。点击“另存 proto”导出新文件；原文件和已有文件不覆盖。快捷键为 Ctrl+O、Ctrl+S、Ctrl+Z、Ctrl+Y。

红色音符边框与列表文字表示同一手指被分配了时间重叠的音符；它是冲突提示，不会自动改指法或删音符。全部 `part=0` 的文件会提示核对，因为 protobuf 默认零值不能区分“没有标注”和“右拇指”。

导出只允许显式修改 `notes[].part/start_time/end_time`，必要时延长 `total_time`；保留原始尾段，不擅自缩短全曲。音高、力度、顺序、其他事件、元数据及 protobuf 未知字段保持不变。未编辑时导出原始字节；含量化步数的文件只允许编辑指法，拒绝同时悄悄改变秒值造成双重时序不一致。输出不自动替换注册乐谱、实验输入或训练配置。

## 三维预览

拖动时间滑块、输入时间后“定位”，或点击“姿态预览”。播放按求解速度逐步推进，包含每个原始起音/松键边界，不保证实时；当前无声。左拖旋转、滚轮缩放、右拖平移。默认从演奏者上方看，左手在画面左侧、右手在右侧，低音到高音从左到右；也可选“对面视角”“俯视”。左右手身份标签随模型保持，视角改变不交换 `part`。

2026-10-21修复了旧CPU投影的相机高度符号及三角形遮挡排序：旧画面从键盘下方向上看。核对原模型右手22个link对应right命名、0–4站点以及世界+Y，左手对应left命名、5–9及−Y；模型/文件编号没有交换。

三维使用当前 `source_supplied_hand_v6` 中的双侧 A3.2 模型，SHA256：

`9299ab01d69563092b65cd4d91b09429ae99aa501cedbb797b9956bd098fece8`

使用当前统一入口的初始高度 0.06 m、ty=0.04 m、yaw=30°，无臂，结构性移除 TZ/Yaw，按当前动作/URDF限位及八指 60°–80°耦合求解。几何场景模板中的参考曲不用于显示或求解；所有活动目标均来自当前导入文件在所选原始时刻的 `part/pitch`。这是当前模型的编辑预览，不是 exper024 旧 checkpoint 的重建。

每个时刻从当前模型初始姿态独立求解，闲置手指保留初始驱动参考并接受原耦合解；不执行速度/加速度限制或动力学。因此它展示的是按键姿态序列，不是已验证的连续物理轨迹。未达到目标会显示毫米误差和对应手指颜色的连接线。同指重叠不会静默择一求解，该指保留参考姿态并列出冲突编号。

目标琴键使用对应分配手指的颜色，与手指实体、指尖编号和时间轴采用同一色表；白键、黑键均同步。既无当前目标也无上一组残留的琴键保持黑白；同一琴键同时分配多个手指时按各指颜色分区显示。颜色只表示谱面目标，琴键 qpos 没有被按下，不代表实际触键。显示表面为44个活动碰撞凸包的简化绘制，未改变远端模型几何。界面编号是本编辑器的交互辅助，不改变训练视频去掉悬浮标签的规则。

2026-10-22新增默认开启的“上一组指法残留”：当前琴键保持手指原色；上一组已松开的琴键按原手指颜色30%＋白色70%显示，并标记“上＋指法编号”。只保留一组，不累计全曲轨迹。组按原始谱面相同起音秒值定义，不做控制帧量化；在当前组之前取上一组，当前最新组已经全部松开而处于间隙时保留该组。仍在延音的音符继续显示为当前原色，同一琴键的当前目标优先于浅色残留。前后拖动、修改指法/时值及撤销均从当前谱面重算，不依赖上一次点击或远端响应到达顺序。可在视角按钮旁关闭残留。这里只叠加琴键指法位置，不生成上一组的额外三维手部姿态或触键状态。

2026-10-23新增默认开启的“下一组指法（浅色斜线）”：严格取当前秒值之后最近的一组原谱起音，和弦同时显示，按即将使用的手指颜色变浅填充，并用斜线及“下＋编号”区分上一组的浅色实填。即使下一组与当前目标落在同一键，也保留当前原色并叠加下一指法的浅色斜线；同一键下一组多指保留各指提示。没有当前目标时，下一组提示优先于上一组残留。曲尾没有下一组，提示自动清空；编辑指法/时值、撤销及向后定位都重算。此提示仅用于显示，不把未来音符纳入当前求解或实际触键。

## 运行与依赖

- 默认模式下，本机运行 Tk 界面、protobuf 编辑与 NumPy CPU 三角形绘制，模型编译/加载及IK仍在远端。本机需要项目 `.venv` 中的 `numpy`、`protobuf`、`note-seq` 和 Python Tk 支持。渲染从最初就是本机CPU绘制；本轮增加内存隔离并修复相机，没有改成GPU渲染。
- `launch_fingering_editor.sh` 要求启动前至少4GiB `MemAvailable`，以独立systemd用户scope运行，`MemoryHigh=384M`、`MemoryMax=512M`、`MemorySwapMax=0`；读取实际内核cgroup值并设置/验证 `memory.oom.group=1`，失败时拒绝运行。直接运行Python入口也必须满足实际cgroup限制。
- 默认模型编译、加载、耦合、IK 经 SSH 在 `volc-a32` 的独立源码目录执行。禁用 CUDA 和 OpenGL，线程数为1。首次启动通常需要等待数十秒；SSH断线显示错误，不静默改用本机。
- 连接配置保存到 `configs/fingering_editor/remote.json`；可选本地后端配置为同目录 `local.json`。默认启动会将旧 `logs/fingering_editor/{remote,local}.json` 逐字节校验后迁移到新目录，已有新配置不覆盖。诊断、会话日志与PID继续保存在 `logs/fingering_editor/`，清理日志不应删除连接设置。
- 远端配置缺失时，编辑器后台自动运行 `scripts/prepare_fingering_editor.py` 恢复，显示初始化进度；失败则显示原因和日志路径，音符编辑仍可用。本地存在固定预览归档时核对其SHA；本地归档缺失时，远端必须仍有SHA完全匹配的固定预览归档，才可恢复独立部署，并核验依赖、资源及上传worker SHA。只复用依赖环境，不导入远端工作区源码。此编辑器继续使用已记录的v6预览版本；恢复配置不将它升级或声称与后续当前训练模型一致。
- 本机窗口退出会关闭 SSH worker。需要重建远端部署时运行 `./.venv/bin/python scripts/prepare_fingering_editor.py`，再启动窗口。
- 用户2026-10-21明确要求评估本地模型构建和求解后，新增显式 `--backend local` 实验路径及 `scripts/stress_fingering_editor.py`。本地重型工作只在独立worker scope内执行，硬上限1.5GiB，内存压力提前终止；没有扩大训练/物理仿真许可。**本轮本地冷构建未通过压力门槛，仍以远端求解为默认，暂不建议日常使用local后端。** 测试设计、命令、保护条件和实测报告见 [本地压力测试](fingering_editor_local_stress_20261021.md)。

## 验证与局限

2026-10-20：4项轻量数据测试通过，覆盖未知字段保留、另存不覆盖、撤销/重做、时序校验、冲突、量化字段拒绝与用户样例原字节往返；实际 Tk 导入、选择、改指、改起止时间、撤销与窗口截图已检查。

远端4个样例时刻（0.01、0.4、1.2、4.0 s）通过有限状态、关节/动作限位、八指角度及琴键位置不变检查。单音的最大目标误差约0.04–0.79 mm；1.2 s和弦约24.95 mm，表示当前局部求解未到目标，不是不可达性的证明。初始化来源、实际请求与返回姿态保存在 `logs/fingering_editor/display_ready.json`、`pose_validation.json`；截图为 `ui_verified.png`。

本轮没有训练、策略评估、视频导出或物理安全验收，也没有变更奖励、当前训练源码归档及其SHA。后续可改进多指局部求解和增加有声播放；当前预览不保证避碰、真实触键或硬件可执行性。
