## 结论：首条绝对位置目标跳变先触发运动，碰撞在后续发生

动作映射代码为`mjlab_env/scene.py:step`：

```text
目标位置 = 下限 + (归一化动作 + 1) / 2 × (上限 − 下限)
```

这表示范围内的绝对位置。动作0对应中点，**不等于不动**。初始腕TX/TY/TZ为0，但右TX范围[−0.7605,0.4605]的中点为−0.15m，左TX范围[−0.4605,0.7605]的中点为+0.15m；当前安装两手Y分别±0.15m，所以两个中点会使手向键盘中央靠拢。TY中点为+0.075m，沿世界−X向琴键内部移动；TZ中点为−0.0125m向下。

该早期策略首条腕部归一化输出接近0，实际给出：

| 自由度 | 初始值 | 第一条目标 | 25ms后实际值 |
| --- | --- | --- | --- |
| 右TX（世界+Y） | 0 | −123.71mm | −21.07mm |
| 左TX（世界+Y） | 0 | +142.26mm | +24.50mm |
| 右TY（世界−X） | 0 | +75.74mm | +12.65mm |
| 左TY（世界−X） | 0 | +70.44mm | +11.93mm |
| 右TZ（世界+Z） | 0 | −11.40mm | −1.80mm |
| 左TZ（世界+Z） | 0 | −12.76mm | −2.39mm |

第一条归一化TY动作右0.00987、左−0.06076，都会映射到约7cm的向内目标；真正保持TY初始0需要归一化−1，保持TZ初始0需要+1。代码把目标一次写入ctrl并保持10个物理子步，没有目标变化率限制或子步插值。

腕部TX的位置误差一开始就产生约−37.11N／+42.68N的未截断比例驱动力需求，TY为+22.72N／+21.13N；40个手指执行器中30个初始比例项已超过力矩上限。以上为初始误差乘gain的估计，不等同实际接触力，也没有把这些物理执行器当作无力矩上限。

实际保存轨迹：到100ms时，两手已沿键盘方向向中间移动81.66mm／75.51mm，同时向琴键内部移动32.64mm／27.24mm。首100ms诊断里最大腕平移速度约1.14m/s；因此25ms一帧的视频很容易看到突然前冲／合拢。

## 时间顺序与反证检查

1. t=0按视频初始qpos做MuJoCo前向检查，没有负距离的手部接触，未发现初始穿插。
2. t=2.5ms首个物理步，腕部已运动；例如左右TX分别−1.02mm／+1.19mm，速度−0.407／+0.476m/s。
3. 按GPU每个2.5ms子步采样，约10ms首次采到手—琴键接触（左中指末节与黑键）。
4. 手内碰撞在保存视频50ms姿态已出现；动态接触缓存首次采到52.5ms，为右中指PIP与无名指PIP。两种检查分别针对当前几何与积分使用的接触缓存，不混称同一个精确时刻。
5. 100ms出现双手之间接触，首先是左右拇指MCP。首秒没有采到手与琴箱等其他部位碰撞。
6. 对照实验保持真实初始控制0.5秒，无手部负距离接触；腕平移偏离最大1.68mm，右手指角度变化最大约0.105°，没有同类大幅前冲。

因此起始“爆冲”的直接来源有明确动作证据：早期绝对位置输出接近区间中点，触发大幅驱动。后续触键、自碰撞与双手相撞会改变运动、带来反作用；这些接触不能倒过来解释首个无接触时已开始的运动。40/400Hz软接触可能影响随后表现，但本次没有做积分器／步长消融，不能量化它的贡献。

### 诊断精度限制

逐子步诊断是在独立GPU实例重新施加视频记录的动作，不是原视频的力传感器记录。首100ms与视频的最大平移误差0.000381mm、角误差7.75e−6rad，足够支持以上早期顺序分析；但到首秒累计最大偏差14.38mm／0.5235rad，故不把首秒重放接触力峰值当原视频精确受力。视频世界坐标位移来自原保存qpos，不依赖重放轨迹。V32-SAC-03仍待定位。

## 为什么新增自碰撞惩罚不能单独保证消除前冲

`self_collision_reward`只在同手部件接触后扣分；它不限制ctrl目标跳变／速度，不处罚正常手指触键，也不负责双手之间碰撞。因此需要策略学会避让才可能改善，不能直接阻止第一步向中点移动。本视频本身来自自碰撞权重0的旧小星星检查点。

后续可比较：首动作从当前ctrl逐渐过渡、限制每步目标变化量、围绕初始姿态输出偏移或调整初始化。它们会改变控制或学习语义，不在本轮擅自启用。论文§2.4／2.6 pp.6–8有子步目标插值；当前已对齐频率，但未采用插值。插值只把目标分散到25ms内，并不等于限制最大速度；后续按项目控制目标和实测选择方案；2026-09-28已取消论文比对与对齐确认流程。
