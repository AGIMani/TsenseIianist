# 训练耗时与开头大幅运动诊断

> 本文是旧step-18000及优化前诊断的历史快照。整周期graph／编译／融合已完成，当前step-15000、自碰撞配置、前100ms逐子步接触和最新训练耗时见[2026-09-18补充实测](startup_height_speed_20260918.md)。

日期：2026-09-18。对象：正式run `sac-20260917-150810-595009` 与最佳 `step-18000.pt` 的已导出视频。本次仅定位问题，没有改训练、动力学、奖励或检查点。

## 1. 为什么5M训练需要约2小时51分

原训练 `summary.json`：10287.112秒，5,000,192条transition，593,056次完整SAC更新，平均约486条采样/秒。

### 独立计时结果

在同一RTX PRO 6000上，保持256环境、batch4096、每向量步32更新、FP32／TF32关闭，预热后计时12个向量步：

| 部分 | 平均每向量步 | 占比 |
| --- | ---: | ---: |
| GPU物理，100子步 | 242.17 ms | 50.16% |
| 32次SAC更新，含replay采样 | 237.46 ms | 49.19% |
| 乐谱／奖励／观测及环境检查 | 2.21 ms | 0.46% |
| replay插入 | 0.68 ms | 0.14% |
| 256环境Actor动作 | 0.26 ms | 0.05% |
| 合计 | 482.79 ms | 100% |

对应约530条采样/秒，与长训练约486条/秒处于同一量级。**这是独立短测，不是历史训练精确计时分解**：各阶段之间显式CUDA同步；replay容量仍为262144，但填充的是重复的16组有效预热transition，并非历史replay；不含初始化、周期评估和保存。初始神经网络从指定检查点加载，仅修改诊断进程内的副本，不保存新权重。

### 两个主要计算负担

1. **物理密度高**：20 Hz控制、0.5 ms物理步长，每控制步100子步；整轮累计500,019,200个“单环境物理子步”。模型138关节、178几何、44网格，含手指自接触和钢琴接触，不能与简单刚体场景速度直接比较。完整双手碰撞形状需要接触求解。
2. **学习更新多**：593,056×4096＝2,429,157,376条batch样本使用次数，含重复采样。学习稳定阶段每新增256条transition，执行32×4096＝131072次样本使用，比例512。Actor／双Critic／目标Critic、反向传播和Adam更新均有计算成本。

原日志前990向量步尚无学习更新，用321.58秒，约788采样/秒；第1000步后开始每轮32次学习，速度下降有明确原因。任务逻辑和replay插入占比很小，把它们全部删掉也不能带来数量级加速。训练不包含视频渲染／音频合成。

**当前已有CUDA图，但只覆盖MJLab单次物理step等操作。** 本地MJLab `Simulation.create_graph()/step()`捕获、调用单物理步图；项目 `PianoScene.step()`仍通过Python循环调用100次。不是整个控制步、任务和32次学习都已编译成一张图。SAC使用eager Torch、`foreach=False` Adam，每次更新还做有限值检查同步；关闭TF32是已验证FP32基线。

优先做不改变任务语义的性能实验：整控制周期多子步图、学习器编译／优化器融合、减少重复小kernel与主机同步。需要分别计时与数值回归才能宣称提速。减少32次更新、改变并行数／batch或放大物理步长会改变学习预算或接触行为，不能只当“无损GPU优化”。

## 2. 开头大幅运动：主动目标跳变，伴随手内自碰撞

### 2.1 原始视频轨迹直接证明的事实

- t=0初始姿态用CPU几何检查没有手部负距离接触。
- 把原初始控制保持0.5秒，GPU每5 ms采样没有发现手部穿插接触；这不是模型一开始就卡死的证据。
- 第一控制步从初始位置直接切到策略绝对位置目标，没有动作插值／速度硬限幅。例子：

| 关节 | 初始 | 第一帧目标 | 目标变化 |
| --- | ---: | ---: | ---: |
| 右中指DIP | 0.200 rad | 1.542 rad | +76.9° |
| 右食指MCP | 0.220 rad | 1.508 rad | +73.8° |
| 左无名指PIP | 0.420 rad | 1.534 rad | +63.8° |
| 左腕TY（此姿态朝世界−X移动） | 0 mm | 86.37 mm | +86.37 mm |
| 右腕TZ | 0 mm | −18.98 mm | −18.98 mm |
| 左腕Yaw | 0 rad | 0.2398 rad | +13.74° |

以上是**目标变化，不是瞬间实际位移**。按初始位置误差计算，40个手指执行器中26个在第一条命令就要求超过现有±0.6 N·m上限的力矩，左右腕yaw也达到各自5 N·m饱和限值。位置伺服因大误差快速运动，遇到关节约束和接触后会被阻挡并产生反作用。

保存轨迹的平均实际变化量（每50 ms、在对应关节和时间段取平均）：

| 时间段 | 手指关节绝对角度变化 | 腕部平移绝对变化 |
| --- | ---: | ---: |
| 0～1秒 | 15.09° | 7.44 mm |
| 1～3秒 | 4.26° | 2.78 mm |
| 3～7.9秒 | 7.12° | 3.46 mm |

开头一秒的运动确实明显更大，不是正交相机制造的视觉放大。

### 2.2 撞到哪里

将视频记录的前60帧动作重新输入独立GPU场景，**每5 ms**读取实际积分步的接触几何与MuJoCo-Warp接触力：

| 部位 | 采样最早接触 | 采样最大单接触法向力 | 峰值时刻 |
| --- | ---: | ---: | ---: |
| 右手掌 ↔ 右小指根部摆动连杆 | 0.025 s | 17.62 N | 0.030 s |
| 右拇指末节PIP ↔ 右食指根部摆动连杆 | 0.035 s | 12.93 N | 0.150 s |
| 右拇指MCP ↔ 右食指根部摆动连杆 | 0.060 s | 14.37 N | 0.115 s |
| 左无名指根部 ↔ 左小指根部摆动连杆 | 0.170 s | 20.65 N | 0.795 s |

这是**仿真单接触力**，不是经过标定的实机测量，也不是每对几何全部接触力之和。接触采样还发现普通指尖与琴键接触；未采到左右手互撞、手撞琴壳或地面。采样间隔5 ms，不能排除两个采样点之间极短接触。

为避免把重新仿真的漂移误认为原视频，另用原视频保存的精确qpos逐帧做纯几何检查：**0.15秒右拇指末节与右食指摆动连杆重叠约2.23 mm；前三秒该碰撞对最大重叠约3.34 mm**。原视频另有左无名指／小指中节接触。图中红色显示右拇指／食指对应刚体：

**诊断边界**：固定动作GPU重放仍有漂移，前三秒与原视频最大平移差4.60 mm、最大转角差0.260 rad；因此表中的力与时刻属于诊断重放。原视频碰撞几何结论来自其原始状态。未做“移除碰撞后重放”的因果消融，不能把全部运动幅度归因于碰撞；已确认的是目标激进、力矩饱和，以及随后出现了实际自接触力。

### 2.3 为什么训练没有避免这些行为

- 当前奖励的 `forearm_reward` 只检查**左右手掌之间**的指定几何接触，不检查同一只手内部的拇指／食指、小指／手掌等自碰撞；这些接触不会触发这个专门的碰撞扣分。能量项仍可能间接惩罚其运动，但不是同一个约束。
- 当前没有命令速度／加速度、自然姿态或手指超速专项惩罚；位置目标可以在每50 ms间隔大幅改变。有限的执行器力矩和关节阻尼不等于速度上限。
- reset是保存的通用初始姿态，第一帧已经需要按乐谱，不是已训练的第一拍手型；策略以较大动作迅速进入可得分区域。
- 手部接触网格和执行器增益仍为暂定（V32-04/05/06/07）；部分碰撞可能与刚性网格凸包近似有关。**本次没有证据判定某一对真实硬件本应互不碰撞**，不应直接屏蔽这些碰撞来让画面看起来平稳。

## 3. 后续处理顺序与论文对照

本次没有改变参数。建议后续先核对上列手内接触的几何范围／允许活动范围，再单独验证起始目标过渡与运动平滑方案，同时观察F1和接触力，避免只把异常藏起来。

根据已确认的论文约定，这些方案涉及之前尚未采用的设计：

| 内容 | 论文位置／做法 | 当前实现及影响 |
| --- | --- | --- |
| 控制插值／时序 | 已登记V32-PAPER-04，40 Hz及子步动作插值对照 | 当前20 Hz、100子步保持一个目标；改插值会改变策略实际控制轨迹 |
| 速度／加速度／超速 | p.11式16～18；Stage2启用手指超速项 | 当前没有对应项；加入会改变目标函数，旧权重不能自动保证保持F1 |
| 接触惩罚 | p.11式19 | 当前只检查双掌接触，论文不期望接触名单仍不全；需为TsenseI定义，而非盲目覆盖所有正常按键接触 |
| 自然姿态 | pp.11～12式20 | 当前没有该项；需要定义本手的自然姿态和单位 |

用户已选论文SAC参数并保留CPU任务奖励，不能据本次诊断自动切换完整论文课程。这些变更由用户决定后另做独立配置与验收。
