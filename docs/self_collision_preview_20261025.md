# MuJoCo自碰撞奖励检查预览

用户选择显示实时接触状态和扣分，不计算缺少人工真值的F1。入口为：

```bash
./launch_piano_preview.sh --self-collision
# 或
./launch_self_collision_preview.sh
```

窗口右侧选择左右手及手指，用鼠标拖动MCP/SW滑条；拇指提供Rot、Rot2、MCP、PIP四轴。四根非拇指的PIP/DIP按当前10°～80°耦合自动计算，并显示只读角度。Wrist页提供当前启用的Tx/Ty/Pitch，TZ/Yaw保持结构性关闭。

- **红色**：该接触计入同手不同手指奖励；列表给出具体body对和穿透深度。
- **黄色**：存在手部接触，但不计入这一奖励。例如同一根手指内部、手指与掌壳。跨手接触也不属于同手项，但训练另有跨手惩罚，不能理解为总体无罚。
- **C**：切换外观网格、碰撞凸包、两者叠加。只改变显示，不修改物理几何或碰撞过滤。
- **E**：显示/隐藏被该奖励排除的手部接触；键/琴体接触保存在完整响应日志，不混入同手列表。
- **Tab / 1～6**：切换左右手/拇、食、中、无名、小指及腕。**T**顶视，**N**复位；场景内左拖旋转、右拖平移、滚轮缩放。

当前计分以原生接触中`distance <= 0`的同手不同指body对为准，同一物理子步内按body对去重。显示的单子步贡献为`−0.1 × 对数`；“Held for one control step”是假定该姿态持续全部50个1000Hz物理子步时的`−min(0.1 × 对数 × 50, 5)`。因此持续一个控制步的一对接触达到−5封顶；只接触一个子步的一对为−0.1，不能将静态显示误解为已经实际扣完−5。

预览是静态接触检查，没有物理积分、真实受力测量或完整控制步执行。滑条输入不受动态速度/加速度轨迹约束，只遵守当前独立关节位置范围和耦合；用途是排查几何/奖励范围，不能据此认证可执行运动或硬件安全。窗口显示UPDATING时，三维姿态和扣分仍是最后一次确认的远端响应，避免把新滑条值配上旧碰撞分数。

## 来源和执行边界

使用当前冻结A3.2源码的同一个MuJoCo3.11.0 MJB，SHA256 `920475c61dc0469779d9f64769c75044140163151461201609ec181a7509fd4f`，父归档SHA256 `1d4a67f15c796a849387ccc967c4960f4ee12d0b18bde2ff81f27a591c23d560`。配置在`configs/self_collision_preview/remote.json`；依赖已有`results/turkish_march_planning_20261024/interactive_replay/model.mjb`，没有本地XML编译回退。

所有动作映射、耦合固定点、模型接触查询在`volc-a32`独立部署的CPU worker执行。启动校验1570个模型/资产/源码散列、scene manifest、固定recipe、模型版本、耦合与奖励参数。每个姿态先在远端记录、回传后在本地JSONL保存，再由本地MuJoCo仅更新显示变换；本地没有`mj_step`、`mj_forward`或`mj_collision`调用。一个请求在途、最多一个待处理快照，拖动不会无界堆积。

本地显示保持独立systemd用户scope：MemoryHigh2300M、MemoryMax3G、MemorySwapMax0，并要求启动前至少4GiB可用内存。未改系统驱动、训练默认奖励、模型、源码归档或运行实验。

每次会话在`logs/self_collision_preview/<session>/`保留远端命令/进程、stderr、完整响应、退出状态及验收报告。远端日志在`task_outputs/collision_preview_sessions/<session>/requests.jsonl`。断线显示错误和旧姿态，不伪造新结果。

## 已完成的检查

253姿态初扫中，左右十指分别MCP0～1.4rad、每0.1rad一步，其他独立坐标保持冻结参考姿态；左右四根非拇指同步屈曲也做相同扫描。这两组全部为0个计分body对。该结论不覆盖任意侧摆、腕姿态或动态过程。

MCP=.7rad下侧摆扫描能触发真实原生接触：例如右中指SW=.35rad，中指/无名指swing连接件产生一对接触，最大穿透约1.142mm，界面显示−.1/子步和保持整步−5。单指屈曲与碰掌壳不会自动计入同手奖励；但屈某一指时如果实际碰到邻指，按当前定义仍应计分。

10秒本机受保护交互检查已验证4个远端更新姿态：食指MCP1.4无罚→中指MCP.7/SW.35出现一对、−.1/−5→复位恢复0；来源合同补验后312渲染帧、峰值约1368MiB、OOM事件0。截图及逐响应断言见`logs/self_collision_preview/preview_verified_contract.png`和`interaction_acceptance.json`。

凸包会填充凹处，不能仅凭接触存在就证明真实CAD外壳相撞，也不能用这次无罚的屈曲扫描证明所有姿态都无误罚。详细扫描和局部几何见证审计随同本轮日志保存；本任务只增加检查工具，未擅自更换碰撞几何或奖励公式。

完整扫描结果见`logs/self_collision_audit_20261025/summary.json`与`contact_sweep.png`：150个单指MCP样本、30个四指同步样本均无计分；72个SW样本中12个计分，最多2对/3.818mm。初态另计1样本，共253。右手中指MCP=.7时，SW约+.31135rad首次触发邻指接触，刚接触时穿透约4.53e−8m也计分。几处接触位置到某侧外观网格的最近距离为约.96–1.57mm，只证明局部凸包表面有差异，未证明两个完整外观网格互不相交，因此未认定为已证实误罚。MuJoCo3.11 `mj_geomDistance`在本任务已见假零反例，附加查询单独标记NOT_FOR_ACCEPTANCE。

后续[初始Ty研究](../logs/palm_y_initial_20261025/README.md)发现两侧掌壳与小指SW连接件在实际首音准备的稳定段仍持续承力；Ty从0.040改为0.020m未改变这两对接触。它们属于黄色排除项，零同手奖励不代表零物理自碰撞。该新准备记录与本工具的253个静态扫描分开，未修改奖励定义或碰撞几何。
