# 首音上方平滑准备：已批准方案

## 已确认需求

用户要求后续每次训练开头的准备段平滑移动到第一个按键位置，并明确选择：停在键面上方，到原谱起音时再按下。保留原谱、指法和真实物理轨迹，不裁剪数据或回写状态掩盖超限。

## 当前事实与参考

- `results/exper042/config.json` 的 `preparation=null`、`preparation_time=0`，该轮未启用准备功能。
- `mjlab_env/preparation.py` 的固定准备仅整体下降；策略准备只确定支撑高度，关节动作由策略决定。现有两种模式都没有首音预定位保证。
- `mjlab_env/source_runtime.py`、`bundle.py`、`scene.py`、`task.py`、`rl_torch/train.py` 共同管理模型重建、reset、动作变换和准备期时间。
- `preview/scripts/preparation_frames.py` 管理准备录制与音频时间偏移，必须同步验收。
- 当前统一入口已经是土耳其进行曲、1000Hz物理/20Hz控制，不能从exper042恢复过时默认值。源码仍从入口指定冻结归档加载，工作区另有未归档修改。

## 方案与取舍

推荐独立的确定性准备控制器，保证定位动作不依赖未训练策略的随机输出。另一种方案是给策略增加首音准备目标，让策略学习就位；这种方式不能保证每轮初始策略都能平滑到达，不符合本次“都会”的意图。仅开启旧固定下降功能不能满足横向和手指定位。

2026-10-25用户明确批准：准备阶段由控制器负责，不作为策略探索阶段；正式策略学习在准备完成后开始，保留原来的学习样本/更新预算。按此方案直接实施、验证、更新默认归档并导出准备视频。

## 推荐方案的具体行为

1. 每只手从本轮原始音符事件及已确认指法读取自己的首个起音；该时刻的和弦整体求解。一只手整曲无音符时保持其参考姿态，不猜填指法。
2. 在当前模型、固定轴、动作范围和八指10～80°耦合约束内求首音上方的预备姿态。首音键面和手指实体净空共同决定悬停位置；仅任务点高于键面不视为无接触证明。
3. 从现有reset参考姿态通过现有驱动执行平滑目标轨迹，起止目标速度与加速度连续。准备时长按位移及当前速度/加速度限制确定并对齐控制周期，留出实际物理稳定时间；保存最终实际时长，不静默挤压原曲时值。
4. 准备结束后交接当前真实状态、实际下发目标和限速器历史，不将qpos/qvel回写成IK解；原谱时间从正常演奏阶段起算，首音前保持无按键目标。
5. 录制完整准备段的真实状态、实际琴键、声音和接触/超限诊断，与后续演奏共享同一次回放的时间说明。首音目标不可达、末端误差过大、误触或非有限状态时报告失败，不宣称已到位。
6. 默认无臂路径先验收；带臂路径必须使用真实刚性装配和现有IK/SDK限速，不能套用无臂mocap运动。未验收的组合明确拒绝，不静默降级。

## 实施与验收范围

- 配置集中于唯一入口与完整config，运行时必须保留所选音符/指法、悬停目标、轨迹时长、实际末端误差和来源SHA。
- 测试覆盖双手首音不同时间、首和弦、缺失指法、整曲单手、不可达目标、交接连续性和回放时间/实际触键一致性。
- 场景构建、IK、物理分析在volc-a32独立工作目录执行；GPU验收通过submit.sh进入Slurm。没有本地仿真。
- 验证后生成新冻结归档及SHA，再更新统一入口。保留已有实验、归档与checkpoint；不将exper042解释为已使用新准备流程。
- 如准备期的奖励/采样语义发生变化，同步唯一奖励总表和变更日志。准备前缀不进入奖励、SAC replay或学习步数；闲指惩罚参考保持原始reset参考，而非首音姿态。未启动训练。

## 物理诊断的验收语义

`valid`只表示首音悬停、无实体触键、目标可执行与真实终态可原样交接；不是全程实际硬限保证。完整物理前缀不进行训练路径的硬状态投影。每个真实关节越界在`joint_excursions`报告，`physical_hard_limits_satisfied`独立标记；非有限状态、终态需投影、耦合无解、终态误差/速度过大或触键仍拒绝。首次参考姿态的耦合诊断保留，终态必须满足耦合容差。
