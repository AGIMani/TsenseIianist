# 2026-10-10：左腕停止后机械臂振荡的原因

本文是Slurm2085、schema2实际腕PD跟随显示方案的历史原因分析。后续schema3已改用连续IK、两层目标制动与刚性装配，并同步固定归档；当前控制合同见[机械臂要求](optional_arm_wrist_ik_requirements_20261008.md)，实验状态见[训练环境总览](training_environment.md)。原记录、分析和隔离对照保留用于追溯。

结论：这次长时间往返来自**只优化下一步位姿误差的 IK 跟随器，与关节加速度硬约束之间缺少面向目标的提前制动**。停止测试的腕部目标超调把臂带到伸展奇异附近，并短暂请求了不可达的完整位姿，触发较大的跟踪误差；之后腕部停住，跟随器仍反复越过目标。速度／加速度硬限确实有效，但不能代替停稳控制。

原因分析当时仅完成定位和CPU隔离对照，尚未修改该受测算法与归档；这不是后续schema3的现状。原现象应称为“持续数秒的反复超调”：延长CPU对照后原算法最终收敛，未证明存在永久极限环。

## 触发过程：目标在高速阶段突然保持，腕部目标限制器出现超调

4s 前轨迹的请求速度已增加至0.42m/s；4s 后位置直接保持42cm，没有安排预先减速段。`target_motion_limits.py` 的速度／加速度投影只能按1.99m/s²逐控制步制动，代码中的 stopping distance 保护针对通道的固定位置边界。

| 时间／量 | 同次记录结果 |
|---|---|
| 4.0s 左移请求／实际左移 | 420mm／343.934mm |
| 4.2s 限幅后实际下发的腕 PD 目标 | 452.858mm，超过420mm目标32.858mm |
| 4.375s 腕部实际左移峰值 | 432.165mm，实际超调12.165mm |

所以最初腕部超调不仅来自物理 PD：**送给 PD 的位置目标已经过冲**，随后真实腕部才响应。将全部现象归咎于腕部 PD 增益不符合记录。

## 放大条件：完整位姿短暂不可达，最终位置靠近伸展边界

使用相同固定基座、包内左臂 URDF 和完整 Link7→手安装，先由腕位置及姿态反算三末端关节共点的腕心，再检查肩部到腕心的距离。

几何必要条件为 `|腕心−肩心| ≤ 上臂最大有效长度 + 前臂长度`。根据 URDF 的偏置和近似 rpy 原值计算，两项分别为0.287563972m、0.314515500m，总上界 **0.602079472m**。计算保留了 URDF 的0.018m偏置及rpy舍入，不把臂简化为无偏置的两根连杆。上界是保守必要条件，不等同完整关节限位工作空间的精确边界。

本次请求腕心距离峰值为0.606573695m，超出上界 **4.494mm**；**4.275–4.590s**，所请求的完整腕位姿不可能精确实现。近伸直处，加权六维Jacobian最小奇异值在4.310s降至约`1.96e−4`，条件数约3689；此处相同的末端变化需要更大的关节变化。

终点对应腕心距离0.600227293m，距离上述伸展上界只剩 **1.852mm**，但已用独立 SciPy 有界全位姿 IK 找到有效解：位置误差低于`1e−6mm`、姿态误差低于`1e−10rad`。因此短暂不可达是触发和放大条件，不能解释腕部停止后数秒的持续往返。

## 持续原因：下一步追位置，缺少以停稳为目标的速度反馈／制动规划

原受测schema2归档内 `arm_follow.py` 的处理链为（行号同样指该旧源码）：

1. `step()` 168行先求只受关节位置边界限制的原始 IK 解。
2. `bounds()` 139–146行由前次 q/v 和 SDK 限值构造下一200Hz子步的位置区间。速度只能在原值附近按 `a_max×0.005` 改变。
3. 173行再在该区间内求更接近腕位姿的解。`solve()` 109–127行的代价只有位置与姿态误差，没有目标剩余距离对应的停车速度、终端速度或后续制动代价。
4. `_stopping_speed()` 144–145行仅用于避开URDF关节最小／最大位置，没有对动态 IK 目标进行提前制动。

速度参与了硬限区间计算，但没有进入停稳目标。结果是：有误差时尽量向目标加速；接近目标时速度仍大；一旦到达或越过目标，受加速度限制又不能立即停下；反向追赶时重复这个过程。即使每步 q/v/a 都合法，整个过程仍会多次过冲。

代码中 `damping=.008` 是 DLS 求解的数值正则项，不是关节运动随时间的速度阻尼。单独把它叫“已有阻尼”不能证明能停稳。行搜索包含零增量候选，只能保证单次求解内部相对**已投影初值**的代价不增；前一实际 q 经常因当前速度而不在下一步可行区间，无法据此推出时间上的误差单调下降。停止段抽查58步，前一q均不在下一步可行区间，25步位姿代价继续上升。

一个直接例子：**8.865s** 末端误差仅 **1.167mm**，但 J1 仍以 **90.105°/s** 运动。该关节最大加速度450°/s²，连续近似制动距离约 **9.02°**，200Hz离散最小剩余位移约 **8.80°**；本步原始 IK 目标与已下发角度只差 **0.108°**。已接近目标的角度误差不足以消除已有速度，于是再次离开目标。

6–9.15s 实际腕 XYZ 范围严格为0，姿态总变化仅约`1.34e−7rad`；此时臂末端误差仍在1.167–103.570mm之间，J1加速度约97.6%的子步处于饱和。原始、不加运动硬限的 IK 位置残差最高仅0.000146mm，显示求解器知道静态目标解在哪里，问题集中在如何在硬限内运动并停下。

## 隔离对照

所有对照从原记录6s的同一个左臂 q/v 开始，固定基座和完整目标位姿，运行额外8s。仅“初速度清零”对照改变v；仅“取消加速度边界”对照取消该限制。其余对照都保留原SDK速度、加速度及URDF位置边界。停稳判据：末端位置误差持续小于0.1mm，且全部关节速度持续小于0.001rad/s。

| CPU对照 | 额外停稳时间 | 说明 |
|---|---:|---|
| 冻结腕部，原 IK／双硬限 | 6.340s | 完全消除手腕位置、姿态变化后仍长时间往返 |
| 记录腕姿后延长末值，原 IK／双硬限 | 6.950s | 最后记录后继续保持；末值冻结后也能最终停稳 |
| 冻结腕部，初始臂速度清零，原算法 | 5.385s | 仅清空初速度并不能避免再次加速和反复过冲 |
| 冻结腕部，仅取消加速度边界 | 0.085s | 峰值加速度达SDK的95.39倍；仅用于定位，不能作为修复 |
| 固定一个有效 IK 解，原位置限幅追踪 | 6.420s | 完全去掉后续换解仍有反复过冲，说明换解不是必要原因 |
| 同一固定 IK 解，加入位置／速度反馈，保留双硬限 | 2.585s | 诊断反馈 `a=16×(q目标−q)−8×v` 再用原可行区间投影；速度峰值为SDK的30.42%，加速度峰值84.74% |

最后两个对照使用完全相同的固定IK解、初态和边界，因此直接隔离了“只追位置”和“同时处理速度”的差别。诊断反馈仅证明保留双硬限也能改善停稳，不是已经验证通过的动态腕跟随生产修复。

CPU与GPU在近奇异、约束切换处会累积微小数值差：记录目标对照前0.1s与原GPU q差小于`4e−16rad`，3.15s后最大差约0.0236rad。因此上述延长后的停稳时间属于明确的CPU对照，不能写成原GPU视频后续必然在同一时刻停止。当前证据证明存在数秒反复超调，也证明它在这些固定目标对照里最终衰减，不能断言永远振荡。

## 修复方向与尚未完成的验证

以下是原因分析当时的修复建议和待验收范围。后续实现已经由最新刚性连接要求替代，不能把这里“原腕部轨迹不被反写”等旧PD合同套入schema3；修复实施与控制验收读取机械臂当前合同，长期学习问题读取训练环境总览。

应保留腕部主导、固定基座及SDK双硬限，在机械臂跟随器中引入面向目标的制动／速度反馈或有限时域轨迹控制；连续IK解和冗余姿态管理处理奇异邻域的敏感性。受限或不可达时允许可解释的残差，并保证固定可达目标能停稳。奖励−5是学习信号，本次未运行策略，不会直接对跟随器施加制动；继续训练或加大惩罚不能替代这一控制实现修复。

受控加速测试还应补充连续减速段，分别验证可达区内启停与临界／不可达目标恢复。修复验收需要覆盖长于本次9.15s的定目标停稳、移动目标、近奇异点、不可达恢复、双侧隔离、全部硬限和原腕部轨迹不被反写；GPU验收仍须经Slurm。通过后再同步运行源码、训练归档/SHA及对应文档。本轮没有将诊断反馈写入训练源码。
