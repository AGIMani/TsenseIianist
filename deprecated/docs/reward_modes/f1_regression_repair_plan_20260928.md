## 1. 目标与证据范围

优先验证两个机制：恢复未来用指的定位激励；减少手指悬停却获得接近满分的指法奖励。验收关注整音漏弹、提前松键和音乐 F1，同时保留当前碰撞、键底与误触要求。

用户提供的历史成对分析为：音乐 F1 .9788→.9002、整音漏弹 1→7、提前松键 3→14；未来奖励受 `1-C` 抑制，漏音时仍有很高的距离分。逐音数值属于用户提供的分析，本次没有重新执行其原始回放。两轮多项配置同时变化，因此这些结果支持优先试验，不能单独证明全部退化的因果。

本次已核对当前源码：

- `mjlab_env/fingering_experiments.py` 确实使用 `C + (1-C)*0.2*F`，其中 F≤0.5；C=1 时未来定位的直接奖励系数为零。
- 关闭当前优先后恢复按当前／未来用指数共同归一化的旧公式。这能恢复未来信号，也会重新引入“未来手指多时当前贡献被稀释”的取舍。
- 现有分阶段奖励为 `0.3*接近 + 0.7*XY对准*键面附近系数*真实键程`。零键程时，每个当前指—键对最多获得 0.3；提前定位部分另按所选聚合公式计算，不能把完整指法项一概称为≤0.3。
- 分阶段奖励仍采用几何与键程代理，没有验证施力一定来自指定手指。其历史 1M 对照曾落后于基线，见 [原对照记录](reward_comparison_20260928.md)。该结果不直接代表当前配置下的效果，但不支持直接设为默认。

当前 A100 作业 935 是另一轮实验：5,000,192 样本已完成，best 在 step9500，三回合音乐 F1 均值 .926381、最低 .925467。后续实验以其完整配置为本机基线；用户提供的 .9002 只作历史证据，不与新组混为同一基线。该运行记录的 149 个源码／模型／动作文件 SHA-256 与当前文件一致。

基线文件：[config.json](../training_mjlab/outputs/hpc/job-935-20260928-191156-583628/config.json)、[summary.json](../training_mjlab/outputs/hpc/job-935-20260928-191156-583628/summary.json)。

## 3. 分组与先后顺序

| 组 | 当前指法优先 P | 分阶段 S | 相对当前基线的变化 | 要回答的问题 |
| --- | --- | --- | --- | --- |
| R：重跑基线 | 开 | 关 | 无 | 当前设置在相同预算／执行条件下表现如何 |
| A：恢复未来定位 | 关 | 关 | 只加 `--no-anticipatory-current-priority` | 未来奖励恢复后，整音漏弹是否减少 |
| B：分阶段指法 | 开 | 开 | 只加 `--staged-fingering-reward` | 减少悬停高分后，持续按压是否改善 |
| AB：组合复核 | 关 | 开 | A 上仅改变 S，或 B 上仅改变 P | 两项是否相互补充或抵消；第二阶段才运行 |

先运行 R、A、B。A 是第一优先候选。B 的 30/70 比例、键面门槛和距离尺度先沿用现有实现，避免一组同时改变多个因素。

**交互解释**：B 会改变 C，因而也会改变 `0.2*(1-C)`。B 即使提高 F1，也不能仅凭总分认定全部收益来自按压项。必须同时报告未来系数、当前按压分和逐音变化；必要时完成 AB。不得把 A、B 各自收益相加作为组合结果。

## 4. 分阶段执行与预算

### 第一步：功能与观测核验

实施时新增本次专用对照计划／汇总入口，提供只生成计划的模式，并逐字段比较实际解析后的配置。**不直接复用 `scripts/run_reward_comparison.py`**：它会关闭正确键子步奖励、预填和尾段，还改变提前定位观测，属于历史实验定义。

复用并补足现有指法、性能开关、训练预算及检查点测试，重点验证：

1. 三组只有指定奖励开关不同；提前定位均 .15 秒，观测／动作均 1231/47。
2. C=.99／1 等边界的当前／未来贡献符合各自公式；当前已分配手指不获得重复未来目标。
3. 分阶段在悬停、真正下压、键底、另一手指按同键时分别记录贡献，明确几何代理的能力边界。
4. 新配置与匹配检查点可严格重建；旧检查点的奖励合同保持原义。
5. 在 Slurm 内各做512×240步功能短训，预期122,880样本、93,696预填、7,296次更新；需跨过实际学习起点。该短训只验收程序和采样合同，不作 F1 选型依据。

### 第二步：约3M样本初筛

- R、A、B 使用 seed42，各 **5860 向量步＝3,000,320 样本**。
- 每组整曲预填93,696条，从第93,697条开始学习；总更新应为 **726,656**。
- 在约2M样本处检查曲线和逐音问题，完整跑到3M再筛选；只因短期 F1 低不提前淘汰 B。数值异常／物理溢出则按原错误处理终止，并报告不完整实验。
- 等预算期间把 `target-consecutive-evals` 设为5862，确保不会由质量早停改变采样预算；best保存及诊断门槛继续生效。
- 同时比较末500k样本区间的评估均值、final、合格best和不经过best资格筛选的最高观察分，不能只挑偶然最高点。

以下为实施时的提交模板，本次没有执行。每次等上一组完成，再提交下一组；三次提交前核对同一运行源码及配置散列：

```bash
# R：重跑当前基线
bash scripts/hpc/submit.sh train --seed 42 --vector-steps 5860 \
  --anticipatory-fingering-time .15 --anticipatory-current-priority \
  --no-staged-fingering-reward --target-consecutive-evals 5862

# A：只关闭当前优先
bash scripts/hpc/submit.sh train --seed 42 --vector-steps 5860 \
  --anticipatory-fingering-time .15 --no-anticipatory-current-priority \
  --no-staged-fingering-reward --target-consecutive-evals 5862

# B：只开启分阶段指法
bash scripts/hpc/submit.sh train --seed 42 --vector-steps 5860 \
  --anticipatory-fingering-time .15 --anticipatory-current-priority \
  --staged-fingering-reward --target-consecutive-evals 5862
```

### 第三步：交互及完整预算确认

- A、B 均有收益，或一个减少漏音、另一个改善保持时，补做 AB 的同预算试验；若直接系数／逐音诊断无法区分两者作用，也补做 AB 后再归因。
- 选择候选后，先做 **基线与候选各一轮5,000,192样本**的完整对照（seed42）。有收益再补 seed43、44 的同种子配对，保留所有结果；单种子优胜只标“初步”。完整等预算组把早停计数设为9768。
- 这些完整对照从头训练。当前 warm-start 不恢复 replay／物理世界，不能把3M检查点再训练2M称为与不中断5M等价。若后续目标改为修复已有策略，另设同一父检查点的显式奖励迁移对照。
- 选定配置、完成多种子与回放验收后，再更新正式入口默认值，并恢复原质量早停计数3。

## 5. 诊断及评分合同

### 演奏结果

| 指标 | 口径 |
| --- | --- |
| 20Hz音乐 F1 | 排除准备／释放尾段；每点评估保存三回合均值和最低值 |
| 200Hz音乐 micro F1 | 使用原控制帧内保持的目标；另报 TP/FP/FN，不与20Hz逐帧F1混用 |
| 整音漏弹 | 按原 MIDI 音符编号匹配激活区间；目标有效区间内没有实际键激活；与“无指键接触”分开报告 |
| 提前松键 | 对成功激活的音报告相对原MIDI note-off的早释次数／时长，同时列相对量化目标的结果及中途断开区间 |
| 起音延迟 | 保留原MIDI与量化目标两种时间基准；同时列成功匹配数／漏音数，防止只剩容易音而平均延迟变好 |
| 物理与误触 | 同手／跨手／键底／键侧接触子步，音乐／准备／尾段错误键子步，尾段最终激活键数 |

重复同音按事件一一匹配，准备前缀统一扣除，时间误差报告5ms采样分辨率。逐音CSV覆盖全部34个音；左拇指C4、右小指A5、右食指D5、右中指E5另作定位重点，不编写曲目特例奖励。

### 机制证据

离线回放采集每个当前／未来指—键对的距离、C、F、用指数、当前与未来奖励贡献、未来直接系数、键面高度、键程／激活、MCP/PIP请求与实际角度及接触几何。

- 用同一份已保存轨迹离线重算不同公式，区分“公式变了”和“策略动作变了”。
- 现有观测包含上帧reward，切换奖励后同权重也可能改变后续动作。因此不把跨奖励的同权重回放视为纯公式对照，也不放宽checkpoint合同。
- 在独立审计作业内采集详细200Hz接触，不把大量同步诊断塞进训练采样循环。复用 `scripts/audit_checkpoint_trajectories.py`，补充通用逐音事件匹配和奖励分解。
- 每个最终候选至少5次标准完整回放、3次详细回放。标准CUDA graph指标与详细回放分别报告；物理浮点差异可能使两条路径分叉，不能将其混成同一轨迹。

## 6. 选型规则

1. **初筛优先条件**：末500k的音乐F1提高，200Hz音乐micro-F1不退步；整音漏弹减少，早释次数／总时长改善，且误触没有明显增加。差值处在重复回放波动范围内时标为未分出优劣，保留到完整预算。
2. **物理条件**：按完整200Hz诊断检查键底和手部碰撞。当前基线best的三次评估为零，候选出现新碰撞则标“音乐改善、物理未通过”，不据此升级正式默认。所有失败组和不合格高分仍保留报告。
3. **完整预算确认**：比较同种子基线／候选的差值、每种子的末段／best／final及重复回放。方向在不同种子间不一致时，不宣布稳定修复；继续定位差异。
4. **最终目标**：沿用现有音乐F1和20Hz音乐micro-F1均≥.99、连续3次完整评估以及准备误触／手碰撞／键底／尾段释放条件。200Hz音乐micro-F1持续独立报告，不能把已有20Hz门槛写成200Hz已经达标。
5. 总reward受公式与时段构成影响，只用于同一配置内部诊断，不作为跨组胜负标准。

若 A 已有效、B 无益，则优先采用 A 的最小改动。若 B 有效而 A 无益，保留 B 并核对其收益中的未来系数变化；AB只以实际结果选型。若均无收益，不增加腕限速／学习率／MCP范围等同步改动。

## 7. 必要时的下一轮公式候选

关闭当前优先会恢复旧分母稀释问题。只有当 A 显示恢复未来信号有效、但当前按压保持受损时，再单独比较固定份额方案。例如当前／未来都存在时 `R=0.9*C+0.1*(2*F)`，无未来时R=C，无当前时保持R=F。

该候选令未来系数不依赖C或用指数，总分仍≤1；代价是混合帧中当前部分最高占0.9。0.1是待测工程候选，**不是本轮已采用权重**，不在 R/A/B 中混入。若现有分阶段门槛在真实成功触键中也频繁给零按压分，先统计键面／接触数据，再独立测试其权重或门槛，不能仅凭分数长期为零就猜测新数值。
