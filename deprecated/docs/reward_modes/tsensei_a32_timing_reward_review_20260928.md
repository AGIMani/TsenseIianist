# 2026-09-28：TsenseI_A3.2 迟按／早松的奖励与时序审计

## 范围与证据

本报告只审计源码、保存配置和本轮完整训练统计，提出候选方案；**没有修改奖励、SAC、控制频率、模型或检查点，没有启动新训练**。单个视频中的迟按／早松不能直接代表所有回合，逐音事件的实际归因应以同一检查点重复回放的 200 Hz 键状态为准。

本轮目录：`training_mjlab/outputs/TsenseI_A3.2_anticipatory_20260928/run-20260928-105754-540954/`。核对 `config.json`、`summary.json` 和源码，训练已经完成 9,766 向量步、5,000,192 transitions，耗时 3,200.80 秒，未达到全部目标门槛。

### best 与 final 不是同一个策略

`best.pt` 为第 9,400 步、1,201,950 次学习器更新。其保存时三次确定性评估：

| 指标 | 实测 |
|---|---:|
| 20 Hz 音乐段逐帧 F1（三次均相同） | 0.9788429164 |
| 20 Hz 音乐段 micro-F1 | 0.9739130435 |
| 20 Hz 音乐段 TP / FP / FN（每回合） | 280 / 0 / 15 |
| 200 Hz 音乐段 micro-F1（三回合均值） | 0.9388240895 |
| 200 Hz TP / FP / FN（回合 0） | 2628 / 19 / 322 |
| 200 Hz TP / FP / FN（回合 1） | 2630 / 24 / 320 |
| 200 Hz TP / FP / FN（回合 2） | 2630 / 23 / 320 |
| 准备期误触（20 Hz / 200 Hz） | 三回合均 0 |
| 手碰撞控制帧 | 8 / 6 / 9 |

FN 是“目标键 × 采样时刻”的缺失数量，不是漏掉这么多个完整音符。20 Hz 的 15 个键帧相当于 0.75 键·秒；200 Hz 的 320～322 个键子步相当于 1.60～1.61 键·秒，和弦中多个键的缺失时间会分别累加。这里不能用 20 Hz 逐帧 F1 直接减去 200 Hz micro-F1 来计算采样损失；同口径 micro-F1 的差距约为 0.0351。

最终 `final.pt` 的音乐段最低 F1 为 0.9467753、平均 0.9489553，低于 best。因此后续实验应从归档 best 做受控分支，不能把“继续最终状态”当作从最佳策略续训。

## 源码能够确认的机制

### 1. 目标键正奖励仍然只看 50 ms 周期末

- `mjlab_env/task_logic.py:84`：目标键正项是 `0.5 × mean Gaussian(1 − normalized_key_travel)`；无错键项占另外 0.5。
- `mjlab_env/rewards.py:215`：开启 `substep_rewards` 后，只把上述“无错键半项”替换为十个子步的均值，目标键下压半项仍使用周期末状态。
- `mjlab_env/rewards.py:250`、`:260`：能耗和旧 Daxian 非目标键下压惩罚使用子步均值。自碰撞原本使用子步并集。
- `mjlab_env/task.py:275`：200 Hz TP/FP/FN 已采集，但只是诊断，不直接成为正确按键的奖励。

因此，在一个 50 ms 周期的大部分时间没有按下，最后才跨过激活阈值，仍可得到很高的目标键正奖励。提前松手若发生在两个端点之间，也可能没有对应的持续时间损失。该机制与“端点看起来基本正确、持续按键质量较差”的统计相容，但不能单独证明每个音符具体发生了哪一种错误。

### 2. 接近激活阈值的浅按几乎拿满分，F1 却仍记为漏键

- `suite/tasks/piano_with_tsensei_hands.py:38`：指尖距离容差 0.01 m；键程容差 0.05，margin 0.5。
- `mjlab_env/task_logic.py:13`：容差是高斯函数；目标键归一化行程达到 0.95 时正项满分。
- `models/piano/piano.py:31`、`mjlab_env/task.py:204`：F1 激活判据为琴键关节距最大角度不超过 0.00872665 rad。
- `models/piano/piano_constants.py:56`：白键最大角 `atan(0.01 / 0.15)`，黑键 `atan(0.008 / 0.09)`。

由以上源码公式直接计算：

| 琴键 | 开始计为激活的归一化键程 | 刚低于阈值时的目标键连续分 | 三音和弦中一键如此漏判的总奖励损失 |
|---|---:|---:|---:|
| 白键 | 0.868907 | 0.941229 / 1 | 约 0.009795 |
| 黑键 | 0.901567 | 0.978627 / 1 | 约 0.003562 |

这里“总奖励损失”仅比较目标键半项，假定其他项相同；不是从实际轨迹测出的总收益变化。它说明奖励与 F1 的排序可能不一致：略微浅按就会漏判，但连续奖励下降很小。

现有几何 humanoid 的上限 0.1、理想完整漏键损失四分之一，是相对于“从完全按下变成完全没按”的预算；**它不保证低于每一种阈值附近的漏键损失**。源码 `mjlab_env/rewards.py:60` 已明确该预算不是全局策略排序证明。因此现在不宜继续增大 humanoid 或叠加大幅平滑惩罚。

### 3. 现有指法奖励不要求把键持续按住

本轮 `staged_fingering_reward=false`。`mjlab_env/fingering_experiments.py:42` 仍用距离分，指尖在目标 1 cm 内即可满分，与琴键是否跨过激活阈值、是否持续按下不同。处于键上方、浅按或刚松开时，距离可能仍足够近。

已有 `--staged-fingering-reward` 将这一项改成 30% 接近、70% XY 对准 × 接触附近系数 × 实际键程（同文件 `:11`）。它是已授权的可选方案，但旧模型 1M 从头对照中明显落后，不应直接作为这次新模型的默认“修复”。从高分策略做相同预算的独立分支更有信息量；若要修改 30/70、渐进调权或增加新的接触判据，属于新的设计决定。

### 4. 提前定位提供悬停准备，没有提前下压或保持时长保证

`mjlab_env/anticipation.py:7` 只为**当前未被乐谱分配的手指**寻找窗口内最近的未来指法；0.15 秒对应 20 Hz 下的三个未来网格。目标位于未按下键顶上方 5 mm（`:29`），不允许提前按键。当前正在奏音的手指不会被这个模块主动拉去未来目标。

`mjlab_env/fingering_experiments.py:47` 未来每指最多拿 0.5，与当前指法共用平均分预算；它不是额外无限叠加的奖励。一个当前按键手指如果紧接着要换键，提前定位模块不会在其仍有当前指法时提供下一个键的这组 50 维专用信息；原 0.5 秒未来琴键窗口仍然可见。这限制了用“把提前时间加长”单独解决所有换指／连音问题的能力。

### 5. 错键风险与漏键损失不对称，提前松手是可能的收益折中

任一非目标键激活会损失当前子步对应的“无错键”半项，还存在非目标键下压惩罚 `0.01 + 0.14 × 键程`（`mjlab_env/rewards.py:15`）。相比上一节阈值附近很小的目标键损失，提前释放以降低下一目标区间的残留误触风险，可能更容易获得高总奖励。

这是由公式推导的候选原因，不能据此声称已经证明策略的内部决策。实际应检查：早松前后目标键连续分、200 Hz FN、下一个区间的错键风险以及各奖励贡献。简单减小错键惩罚可能提高 recall 却恶化 precision；简单增加保持奖励也可能导致拖音，不建议盲调单一惩罚权重。

### 6. 腕部限速频繁触发，但不是已证实的唯一迟按原因

本轮仍显式使用 `configs/control_limits/generic_wrist_rate_20260927.json`：TX/TY 目标变化率 1.2 m/s，Pitch 4 rad/s；每 50 ms 最多改变目标 6 cm / 0.2 rad。机械位移和关节实际速度不等同于目标变化率。

best 约 31.1% 的受限通道—帧触发变化率限制，176～177 个控制帧至少一通道触发，位置裁剪为 0。该统计值得逐迟按片段比对“请求目标／执行目标／实际姿态”，但不能据此直接解除限制；大幅请求也可能本来就在用 PD 误差换取驱动力。既往移除限速不能修复其他旧策略的结果同样不能代替新模型的实测。

### 7. 未发现此处的统一错一帧或 reset 污染证据

`mjlab_env/task_logic.py:134` 在推进索引前，以 `applied_index` 的目标对本次实际动作结果计分；随后更新索引和下一观测。`rl_torch/train.py:854` 先写入终态 transition，再局部 reset。没有看到把 reset 后姿态误当音符终态的错误。

末曲 discount 保留原 CPU 合同为 1（`task_logic.py:167`）；SAC target 乘配置 gamma（`rl_torch/sac.py:182`）。本轮 gamma 0.8，0.15 秒之后奖励相对权重为 0.512，0.5 秒为约 0.107。短有效时域可能影响远期准备的收益，但这不是迟按的实测因果证据，也不是本轮首选修改。不得为此自行改为论文 gamma 或同时改学习率。

## 优先级方案：先对齐持续按键质量，再调整动作能力

以下是候选计划，**不是已经实施或已获新设计授权**。三种学习率继续保持用户最新要求的 3e-4。

### P0：建立逐音事件诊断与固定 best 基线

从同一归档 best 重复完整回放，按乐谱音符报告：第一次有效按下延迟、结束前提前释放时长、结束后拖音、音符内部断奏、完全漏音；同时保留 20 Hz 原 F1 和 200 Hz micro-F1、precision、recall、碰撞。区分持续音与相同音高的重复音；时间容差评价只作附加诊断，不替换当前正式 F1，不移动乐谱来掩盖错误。

### P1：原按键奖励预算内加入“按对并保持”的子步占用率

推荐新可选模式，保留原按键总尺度、原错键规则与小幅 humanoid，将目标键半项替换为：

`r_on = (1 − λ) × 连续键程分的子步均值 + λ × 目标键实际激活的子步占用率`

占用率是本控制周期内每个目标键真正跨过当前激活阈值的物理子步比例，再对目标键平均；目标为空时目标键项为 0。候选 λ 应先做小规模独立对照，例如 0.25 和 0.5；不能把它当成已确认最优值。它同时降低“最后瞬间才按中”和“还差一点点却拿高奖励”的收益，保留连续键程信号帮助学习。谱面结束后原错键项会抑制拖音，无需强制关节保持或按曲目硬编码时长。

保持200 Hz物理与20 Hz动作即可利用现有子步采集，不需要先增加物理子步数量。若减少新增选项，可以先测“只把原目标键连续分改为子步均值”，但该版本仍保留阈值附近奖励过高的问题，应单独记录两种作用。

这是独立工程设计，后续已按用户要求实现，见[正确键奖励修复](target_key_reward_fix_20260928.md)。2026-09-28起已取消论文比对和对齐确认流程。新奖励的 critic 目标分布改变，续训必须采用显式奖励合同迁移和可追溯的新分支，不能静默加载成原奖励继续训练。

### P2：现有参数的独立短测

1. 提前定位 0.15 对照 0.20 秒：仅测试更早接近是否缩短实测迟按，不同时解除腕速或更改奖励。规则与参数已存在，但更长窗口的收益尚未证明；同指连续换键仍有上述限制。
2. 在 best 基础单独开启现有分阶段指法：用于验证真实下压的指法信号是否改善 recall。保留旧模型失败对照，不能默认它会在新模型胜出。
3. 限速敏感性：只在延迟事件确实与限速有关时进行受控回放或短测，保存请求目标／执行目标／实际坐标，拒绝通过新增卡键或碰撞换分。不能通过小星星专用 X 窗口调整解决其他曲目的可达性。

这些是已有可选机制，不需要重新发明公式；选择用于正式新训练仍应以本轮实际测量和用户请求范围为准。

### P3：只有前两级仍有固定时延瓶颈，才评估新的观测／控制改动

候选为增加目标音符剩余保持时间／启音时间、真实关节速度，或改变控制频率。论文 pp.7–8 §2.5含速度与未来指法，p.8 §2.6为40 Hz控制与子步插值；当前为20 Hz、周期内保持。新观测会改变检查点维度，频率变化会改变谱面网格、每秒决策数、折扣物理时域、吞吐和回放合同，不能当作只调一个参数且其余完全相同。

不要直接提高 Kp、改机械限位或全局提前播放乐谱来追求 F1；这些改变分别影响接触稳定性、可达性和评价语义，当前没有足够证据支持。

## 实验判据与未解决项

- 同一归档 best、相同种子／样本预算／配置，仅改变一个因素；至少看重复回放，并在候选晋级后验证其他带指法曲子。
- 优先减少迟按、早松与断奏 FN；同时要求 precision 不明显下降、错键子步和手碰撞不恶化。不能只看训练 return 或单个最高 F1。
- 不调整原 F1 激活阈值、乐谱起止或容差来获取表面改进。
- `V32-TIMING-01`：200 Hz 正确按键持续性奖励与激活阈值对齐候选尚待用户决定和实测。
- `V32-QUALITY-01`：当前 best 未达音乐 F1 0.99，手碰撞仍存在；正式评价应保留多个口径。
- 既有掌壳 `base_link` 键底诊断遗漏保持待处理；当前“键底 0”不能作为全手无卡键的证明。本报告没有更改其名单。

本次验证为静态源码审计、JSON统计读取及按源码公式的数值核算；不把候选机制解释写成已验证的训练提升。
