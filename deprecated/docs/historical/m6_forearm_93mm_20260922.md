## 为什么之前手会脱离机械臂

此前手由原有五个虚拟腕自由度驱动，机械臂是单向随动的视觉模型。手可以先到目标，而机械臂受关节速度、关节限位和工作空间约束；快拖动、奇异姿态或不可达目标都会出现间隙。

现在在每次预览更新时，对手腕目标做可达性检查：差分 IK 保留关节位置／速度限位，逐步缩短腕部移动，只有末端误差足够小才接受该段位移；找不到合适增量则保持上一组已连接姿态。手和臂共同停在能够保持连接的位置，界面打印受限目标距离。初始化若无法连接会明确报错，要求修改安装／初姿，而不是带着间隙启动。

GPU 采用批量 Torch 正运动学、Jacobian 和阻尼差分 IK，一次并行求解 8 个步长候选，无逐环境 CPU IK。新 M6 场景在每个 40 Hz 控制周期末应用腕部可达约束，并同步 mocap；控制周期内原 400 Hz 手／琴物理仍运行。**这是运动学约束，不是实体刚性焊接；周期内瞬时轨迹不具有真实机械臂动力学保证。** 快速／不可达请求会被限制，不能把“跟随不脱开”理解为整个虚拟腕范围均可达。

源预览开启机械臂时，P 默认保存实际 `qpos`，防止把未能到达的 Control 目标保存为新初姿。暂停时手指尚未到达的滑块目标需先运行物理再保存；`--save-pose-source ctrl` 仍可显式选择原目标方式。无机械臂时默认保持保存 ctrl。

## GPU 场景、奖励与兼容

已生成独立新包：`training_mjlab/outputs/m6_93mm_clair_20260922_final/scene` 与 `task`，沿用此前月光 mixed_v1 的物理源场景和完整指法任务。动作仍 51，观测仍 2070，40/400 Hz，0.5 秒前瞻。每环境单独维护双臂 14 关节 IK 状态，reset 只重置选中的环境。

- `scene.xml` 是物理模型，无机械臂接触力、无新增策略关节／执行器。
- `collision_query.xml` 是单独查询模型，在控制周期末用同一 GPU 几何状态检测明确的臂接触对，不进入约束求解器。原手／琴物理接触参数不改。
- task 新增 `forearm_collision_pairs`，Torch 按明确名单计分；旧冻结 scene/task 没有 M6 字段，仍走原路径。
- GPU CCD 对中心几乎完全重合的凸包出现过漏检；已加严格内接球相交补充判定。球完全在对应凸包内部，不扩大检测区域，不能替代其余凸包 CCD。真实重合正例、臂—手正例和排除反例已覆盖。
- GPU 快照、实时预览及新录像保存／重构 mocap 位置姿态，避免回放时机械臂停在原点。手动 GPU 预览仍需解除暂停后消费 Control 目标；暂停直接摆腕用源预览入口。
- 新任务的手腕可达约束和奖励与旧任务不同；旧检查点不应冒充在本配置上训练。机械臂关节状态未加入观测，冗余 IK 状态可能使任务具有部分可观测性，后续正式训练须评估。
- 此次没有重用旧 CPU 轨迹冒充完整 CPU/GPU 对照；新包移除旧参考轨迹，保留原谱／指法合同和独立新增测试。默认训练入口仍指向原小星星包；使用新机械臂必须显式指定下面路径。
